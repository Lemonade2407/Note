# 第一章 操作系统
## 导论
### 定义
- 操作系统的本质是一个大型程序
- 程序运行流程：见计组
- **操作系统（Operating System，OS）**：控制和管理整个计算机系统的硬件与软件资源，合理地组织、调度计算机的工作与资源分配，进而为用户和其他软件提供方便接口与环境的程序集合
- 操作系统的目标：
	- 方便性：提供良好的用户接口，方便用户使用计算机
	- 有效性：提高系统资源利用率和系统吞吐量
	- 可扩充性：方便地增加新的功能与模块
	- 开放性：遵循国际标准，便于不同系统互联
- 看待操作系统的三个视角：
	1. 资源管理者：管理处理机、存储器、I/O 设备与文件
	2. 用户与计算机硬件之间的接口：向上提供命令接口、程序接口（系统调用）与 GUI
	3. 扩充机器：在裸机上覆盖一层 OS 后，用户看到的是一台功能更强、使用更方便的“虚拟机器”
### 作用
- 裸机：未安装任何软件的计算机（包括操作系统）
1. 连接软件与硬件，提供操作硬件的接口
2. 管理计算机资源（内存分配、CPU分配等）
3. 扩充机器：把裸机改造成功能更强、使用更方便的虚拟机器（“虚拟机”观点的来源）
### 发展历史
1. 手工操作阶段（无操作系统阶段）
	- 计算机价格昂贵
	- 程序设计采用机器语言
	- 输入输出用纸带卡片
	- 使用时占用所有资源
	- 一次只能完成一个功能，串行执行
	- 手工操作效率低下，CPU等待时间长，资源浪费
2. 批处理阶段（操作系统雏形）
	- 人们设计批处理管理程序（监督程序），实现程序的自动转换处理
	1. 单道批处理系统
		- 特征：自动性、顺序性、单道性
		1. 联机批处理：
			- 操作员一次性输入一批程序，计算机逐个程序处理，直到处理完一整批。
			- 程序从输出到打印都在CPU控制下进行。
			- CPU与I/O设备之间速度不匹配，效率低。
		2. 脱机批处理：
			- 脱机指输入输出操作脱离主机控制
			- 系统由主机和卫星机（外围机）组成
			- 卫星机只负责控制I/O设备，主机只负责计算
	2. 多道批处理系统（操作系统诞生）
		- 特点：并发性（时间段内多个程序在执行，但某时刻只能执行一个程序）区分于并行性（多核，一时刻可以同时执行多程序）
		- 允许在内存中同时存放多个作业，CPU以切换的方式为他们服务
		- 作业可以轮流使用CPU和输入输出设备
		- 为解决程序切换问题引入**中断技术**
3. 分时操作系统
	- 多道批处理系统响应时间可能很长
	- 分时技术将处理器的运行时间分成时间片，按时间片轮流处理作业
	- 特征：多路性（按分时原则为多用户服务）、独立性（用户之间独立）、及时性（用户请求回应快）、交互性（用户可与系统交互）
4. 实时操作系统
	- 需要系统在比时间片还短的时间内作出处理
	- 特征：实时性、可靠性
	- 分类：
		- 硬实时系统：必须在绝对严格的规定时间内完成处理（导弹控制、飞行控制），超时后果严重
		- 软实时系统：能接受偶尔违反时间规定（订票系统、多媒体播放）
- 多道批处理的优缺点：资源利用率高、系统吞吐量大；但平均周转时间长，且无交互能力
- 分时系统的缺点：不能优先处理紧急任务（实时性差）；时间片过小则切换频繁、系统开销大
- 实时系统的特点：对及时性和可靠性要求最高，通常不追求资源利用率
### 按功能对操作系统分类
| 类型 | 主要特点 | 典型场景 |
| --- | --- | --- |
| 批处理系统 | 成批处理作业，吞吐量大，无交互 | 大型机后台作业 |
| 分时系统 | 时间片轮转，多用户交互 | 多用户主机 |
| 实时系统 | 在严格时限内响应，可靠性高 | 工业控制、导弹、订票 |
| 网络操作系统 | 在原有 OS 上增加网络通信与资源共享功能，各机自治 | 局域网服务器 |
| 分布式操作系统 | 统一管理多台计算机，任务可分布并行执行，用户像使用一台机器 | 集群、分布式计算 |
| 个人计算机操作系统 | 面向单个用户，强调交互与易用 | Windows、Linux 桌面 |
| 嵌入式操作系统 | 面向专用设备，代码小、可裁剪、实时性强 | 家电、车载、物联网 |
## 操作系统的运行环境
- 硬件给操作系统的支持
### 中断机制
- 指CPU暂停正在执行的程序，转去执行中断服务程序，执行完中断服务程序后再返回原被中断程序中继续执行
- 分为**外部中断**和**内部异常**
#### 外部中断
- **外设**完成任务或发生某些特殊事件，外设向CPU发出中断请求
- 每条指令执行后，CPU会主动查询有无中断请求
1. 可屏蔽中断：通过可屏蔽中断请求线INTR向CPU进行请求的中断。被屏蔽的I/O设备发送的中断请求不会被送到CPU
2. 不可屏蔽中断：紧急硬件故障，通过不可屏蔽中断请求线NMI向CPU发出中断请求。
##### 中断处理流程
1. 检测到外部中断信号，当前CPU允许响应中断
2. 中断响应：
	1. 关中断：禁止新中断，防止打断现在的中断程序。通过设置中断允许触发器IF实现，置1开中断，置0关中断
	2. 保存断点和程序状态：将程序的断点送到栈或特定寄存器中，被中断的程序状态字寄存器PSW的内容也要保存在栈或特定寄存器中
	3. 中断识别：确定发出请求的中断源，获取中断服务程序入口地址。分为非向量中断和向量中断
		1. 向量中断中，每个中断源有对应的中断编号。
		2. 中断控制器通过INTR向CPU发送请求
		3. CPU通过INTA进行中断响应
		4. 中断控制器将中断源编号通过数据总线发给CPU
		5. CPU将中断号作为索引到中断向量表中查找中断程序入口地址（即中断向量），送入PC
	4. 执行中断服务程序
		1. 单重中断：不能被其他中断请求打断的中断
			1. 步骤：保护现场、中断处理、恢复现场、开中断、中断返回
			2. 执行中断服务程序期间不再响应新的中断请求（关中断），处理完毕恢复现场后才开中断并返回
		2. 多重中断：可以响应其他中断请求的中断，又称中断嵌套；处理过程中开中断，按中断优先级决定是否响应新请求

#### 内部异常（内中断）
- CPU在执行指令时，在其**内部检测到的**与正在执行指令相关的事件
- 分为三类：故障(fault)、陷阱(trap)、终止(abort)
##### 故障
- 引起故障的指令被启动后但未执行结束时，CPU所检测到的与指令执行相关的意外事件
- 无法被修复的故障：无法回到被中断程序，终止当前程序
- 可修复的故障：可返回发生故障的指令，断点为当前发生故障的指令
##### 陷阱
- 预先安排的异常事件
- 执行到陷阱程序后，处理终断，然后返回到陷阱指令的**下一条**指令执行
##### 终止
- 执行指令过程中发生严重错误
#### 外中断与内中断的对比
| 比较项 | 外中断（中断） | 内中断（异常） |
| --- | --- | --- |
| 来源 | CPU 外部（外设、时钟、硬件故障） | CPU 内部（指令执行过程中检测到的事件） |
| 触发方式 | 异步，与当前执行的指令无关 | 同步，由当前执行的指令引起 |
| 典型例子 | 时钟中断、I/O 完成中断、键盘中断 | 溢出、缺页、除零、断点（陷阱）、非法操作码 |
| 返回点 | 被中断指令的下一条指令 | 故障：返回当前指令重新执行；陷阱：返回下一条指令 |
- 系统调用属于内中断中的**陷阱（trap）**，是用户程序主动“陷入”内核的唯一途径
### 特权指令和非特权指令
- 程序分为操作系统程序和用户程序
- 程序由指令构成
- 指令分为特权指令和非特权指令
#### 特权指令
- 只有操作系统才有权使用
- 通常涉及：改变机器状态、修改特殊寄存器、涉及外部设备的输入输出
- 例如：开中断/关中断、设置时钟、清内存、修改 PSW、I/O 指令、停机指令
#### 非特权指令
- 用户程序可以使用的指令，如算术运算、逻辑运算、取数、访存、转移等
- 只能访问自己的存储空间，不能直接访问系统资源
- 若在用户态执行特权指令：CPU 拒绝执行并产生异常，通过中断机制陷入内核态处理（常见结果是终止该程序）
### 处理器状态
- 为了实现CPU区分程序执行权限的能力，CPU有不同的执行状态
- 根据运行程序对资源和机器指令的使用权限，把处理器设置为不同状态
#### 管态
- CPU执行操作系统程序时的状态，又称为特权态、系统态、内核态、核心态
- CPU可以执行所有指令，包括各种特权指令，也可以使用所有资源，访问所有寄存器和存储区域，并具有改变处理器状态的能力
#### 目态
- CPU执行用户程序时的状态，又称为普通态、用户态
- CPU执行能力受限，不能使用特权指令，不能直接使用系统资源，也不能改变CPU的工作状态，且只能访问这个用户程序自己的储存空间
#### 用户态与内核态的转换
- 用户态 → 内核态：由**中断、异常、系统调用**（陷入指令 trap）引起，三者都会使 CPU 转到内核态执行
- 内核态 → 用户态：由操作系统执行一条修改程序状态字 PSW 的特权指令完成
- 用户程序不能直接修改 PSW 切换到内核态，只能通过中断、异常、系统调用进入内核态
- 状态切换需要保存和恢复现场，有额外开销，切换过于频繁会降低系统效率
### 系统调用
- 系统调用时操作系统提供给用户程序的相关过程（函数），为用户程序实现一些服务。（通常需要特权指令/访问核心资源）
- 实现原理：用户程序通过访管指令，主动陷入异常，切换到操作系统程序来为其实现某种功能
- 中断和异常时用户态到核心态转换的途径
- ![[系统调用过程.svg]]
#### 分类
- 按功能分为五类：
	1. 设备管理：请求设备、释放设备、启动设备
	2. 文件管理：打开、关闭、读、写、创建、删除文件
	3. 进程控制：创建、终止、阻塞、唤醒进程，分配与回收资源
	4. 进程通信：消息传递、共享存储区的申请与释放
	5. 内存管理：申请、释放内存，查询内存使用情况
#### 执行过程
1. 用户程序按约定的系统调用号，把调用号与参数送入指定寄存器，或把参数压入栈、放入参数块
2. 执行陷入指令（trap/访管指令），产生内中断，CPU 由用户态切换到内核态
3. 内核根据系统调用号查系统调用表，转入相应的服务例程执行
4. 服务例程完成后恢复现场，返回用户态，并把返回值带回用户程序
#### 与普通函数调用的区别
| 比较项 | 系统调用 | 普通函数调用 |
| --- | --- | --- |
| 执行状态 | 由用户态切换到内核态 | 始终在用户态 |
| 权限 | 可访问核心资源、执行特权指令 | 只能访问自己的地址空间 |
| 实现方式 | 通过陷入指令进入内核，由内核例程完成 | 在用户程序内直接跳转到函数代码 |
| 返回 | 处理完后返回到用户态继续执行 | 直接返回调用处 |
- 系统调用是用户程序使用操作系统服务的**唯一途径**（通常由库函数封装后调用）
### 操作系统内核
- 操作系统的不同功能分别设置在不同层次。只要分为操作系统内核和系统调用接口
- 操作系统内核时计算机上配置的底层软件，通常由一些与硬件紧密相关、运行频率较高的程序共同构成。（时钟管理、中断处理、设备驱动......）
#### 支撑功能
- 为**操作系统其他模块**提供所需的基本功能
- 最基本的支撑功能：中断处理（最基本）、时钟管理和原语操作（原子操作）
#### 资源管理功能
- 进程管理、存储器管理、设备管理
#### 时钟管理与原语
- 时钟管理：向用户提供标准时间（日期、时刻）；通过时钟中断为系统计时，用于时间片计时、实时任务定时、统计进程执行时间
- 原语：由若干条指令组成、完成某一特定功能且**不可分割**（原子性）的程序段
- 原语的原子性由**关中断/开中断**保证：进入原语前关中断，执行完再开中断，期间不会被中断打断
- 内核中常见的原语：进程创建/撤销原语、阻塞/唤醒原语、进程切换原语
## 操作系统的特征及功能
### 基本特征
- **并发**：两个或多个事件在同一时间间隔内发生（宏观同时、微观交替）；并行是指多个事件在同一时刻发生（需要多处理机）
	- 并发是操作系统**最基本**的特征，其他特征都以并发为前提
	- 单处理机系统只能并发，不能并行
- **共享**：系统中的资源可供内存中多个并发执行的进程共同使用
	- 互斥共享方式：一段时间内只允许一个进程访问该资源（如打印机、临界资源）
	- 同时访问方式：允许多个进程“同时”访问（宏观同时、微观交替，如磁盘、可重入代码）
	- 并发与共享互为存在条件：没有并发就谈不上共享，没有共享并发进程也无法推进
- **虚拟**：把一个物理上的实体变成若干个逻辑上的对应物
	- 时分复用：如虚拟处理器（多道程序分时使用 CPU）、虚拟设备（SPOOLing 技术）
	- 空分复用：如虚拟存储器（内存与外存结合，逻辑上扩充内存容量）
- **异步**：进程以不可预知的速度向前推进（走走停停），何时执行、何时暂停、何时完成都不确定
	- 只要运行环境相同、初值相同，异步方式下的运行结果也应当相同
### 用户接口
- 可分为命令控制接口和程序接口
#### 命令控制接口
- 作业控制方式：脱机控制方式与联机控制方式
- 脱机控制方式（脚本）：用户将对作业的要求以作业说明书的方式提交给系统
- 联机控制方式（终端）：用户利用系统提供的的命令和系统会话
#### 程序接口
- 操作系统面向程序员的接口，由一组系统调用组成
#### 图形用户界面 GUI
- 通过图标、菜单、窗口等图形元素操作计算机，用户无需记忆命令
- 严格来说属于命令接口的图形化实现，是当今个人计算机上最主要的用户接口
### 操作系统的功能
- 从资源管理角度，操作系统有五大功能：
	1. 处理机管理：进程控制、进程同步、进程通信、进程调度、死锁处理
	2. 存储器管理：内存分配与回收、地址映射、内存保护与共享、内存扩充
	3. 设备管理：缓冲管理、设备分配、设备处理、虚拟设备
	4. 文件管理：文件存储空间管理、目录管理、文件读写管理与保护
	5. 用户接口：命令接口、程序接口（系统调用）、GUI
## 操作系统的引导、结构以及虚拟机
### 操作系统的引导
- 操作系统负责把待执行程序调入RAM，然后修改PC的值，跳转到该程序执行。
- ROM中保存了一个64KB的BIOS程序，是操作系统引导的核心。
- 引导流程：
	1. 开机时，PC强制初始化为FFFF0H，即BIOS入口地址（包含无条件转移指令）
	2. 执行无条件转移指令，跳转到BIOS主体代码部分；进行加电自检（检查硬件状态）；建立中断向量表并填写中断例程
	3. BIOS完成基本工作后，加载CMOS参数；CMOS存储用户通过BIOS界面修改的配置数据（包括系统启动时的设备检测顺序）；BIOS将控制权交给第一个检索到的可启动存储设备（将该存储设备的主引导记录MBR（是一段程序，记录了存储设备的存储结构）加载到内存）；
	4. 若读取磁盘MBR，其中保存了操作系统的分区被称为活动分区；每个磁盘分区有自己的分区引导记录PBR，PBR也是段程序，负责加载该分区的操作系统引导程序
	5. 若当前活动分区是C盘，则MBR会将C盘的PBR程序加载到内存
	6. 执行PBR，找到启动管理器BOOTMGR加载至内存
	7. 启动管理器加载操作系统内核
### 操作系统的体系结构
#### 无结构
- 早期，设计者只关注具体功能的实现，缺乏整体设计的视角，操作系统是各种函数互相调用
- 程序错误很多，难以调试；程序难以阅读和理解，增加了维护人员的负担
#### 模块化结构
- 操作系统是按照功能划分的独立模块，即模块-接口法
- 关键问题：模块的划分和模块的独立性；衡量独立性的标准是内聚性和耦合度
- 优点：提高OS设计的正确性、可理解性、可维护性、可适应性；加速OS的开发过程
- 缺点：各模块间的接口规定很难满足实际需求，各模块的设计很难找到一个可靠的顺序
#### 分层结构
- 操作系统的所有功能模块分别排列成若干层，各层之间的模块只能是单向依赖或单向调用关系
- 自底向上的分层设计的基本原则：每一步设计都建立在可靠的基础上，规定每一层仅能使用其底层所提供的功能和服务，这样可使系统的调试和验证都变得比较容易
- 优点：容易保证系统的确定性，方便扩充和维护
- 缺点：系统效率降低
#### 宏内核
- 将进程管理、内存管理等核心功能都放在内核中
- 优点：效率高
- 缺点：内核代码难以维护，系统稳定性差
#### 微内核
- 将内核中最基本的功能保留在内核，将其他功能移到用户态执行，以服务程序的形式存在。
- 微内核的操作系统分为两大部分：微内核和多个服务器
- 原理：机制与策略分离；机制指实现某一功能的具体执行机构；策略指借助某些参数和算法来实现该功能的优化；一般机制放入微内核，策略放入服务器
- 优点：扩展性和灵活性；可靠性和安全性；可移植性；分布式计算
- 缺点：频繁状态切换，执行开销大
#### 外核
- 外核将硬件资源的管理权下放给应用程序，内核只负责资源的**保护与分配**（如为进程分配物理内存块、磁盘块），而不再负责资源的抽象与管理
- 应用程序通过链接**库操作系统（LibOS）**来直接操作硬件，由 LibOS 实现传统操作系统的功能（如进程、虚拟内存、文件系统）
- 优点：减少了传统操作系统的抽象层次和地址映射开销，灵活、可定制（常用于高性能计算、虚拟化等场景）
- 缺点：应用程序需要自行实现资源管理逻辑，系统复杂度高、兼容性差
### 虚拟机
- 在软件中模拟计算机
#### 虚拟机管理程序
- 用于实现虚拟机所需要的硬件
##### 第一类虚拟机管理程序
- 直接运行在裸机上，拥有最高权限
- 虚拟机上的操作系统运行在用户态，特权指令是管理程序模拟执行的
##### 第二类虚拟机管理程序
- 需要利用宿主操作系统提供的创建进程、分配资源等服务，特权指令是宿主机实现的
- 将操作系统安装在虚拟盘上；虚拟盘实际上是宿主操作系统中的一个大文件
# 第二章 进程
## 进程与状态转换
### 初识进程
- 进程：一个正在运行的程序，包含了当前运行程序的所有信息，包括代码、数据、CPU信息、资源
- 进程的数据结构称为进程控制块PCB
- 进程是系统进行资源分配和调度的一个独立单位
- 一份程序可以创建多个进程
#### 进程的组成
- 进程实体（进程映像）由三部分组成：
	1. PCB（进程控制块）：操作系统管理进程所用的数据结构，是进程存在的**唯一标志**
	2. 程序段：进程要执行的代码
	3. 数据段：进程运行过程中产生的数据（全局变量、堆、栈等）
- 进程与程序的区别：
	- 程序是静态的（存放在磁盘上的指令集合），进程是动态的（程序的一次执行过程）
	- 程序可以长期存在，进程有生命周期（创建、运行、终止）
	- 一份程序可以对应多个进程，一个进程也可以执行多个程序
### 进程的特征
- 动态性：进程的状态是不断变化的
- 独立性：进程是一个能独立运行、独立获得资源和独立接受调度的基本单位
- 并发性：多进程同存于内存中，且能在一段时间内交替运行
- 异步性：进程按照异步方式运行，会产生不可再现的结果
### 进程的创建与终止
#### 进程的创建
- 操作系统启动
- 用户发出请求
- 正在运行的进程，执行了创建进程的系统调用
#### 进程的终止
- 自愿退出
- 致命错误
- 被其他进程所杀
### 进程的状态与转换
#### 进程的状态
- 创建态：被创建时
- 就绪态：被创建后，进程已具备运行的条件，但是CPU正忙
- 执行态：进程被CPU执行时，进程数目必须小于或等于CPU数目
- 阻塞态：进程暂停执行时，即使CPU空闲也要等待某一事件完成
- 终止态：进程运行结束
- ![[进程五状态转换图.svg]]
- **最基本最核心**的是**执行、就绪和阻塞**这三种状态
#### 进程的转换
##### 运行态->阻塞态
- 一般进行输入输出或者打印的时候
##### 运行态->就绪态
- **CPU的调度程序**认为进程已运行足够长时间（时间片用尽）或被高优先级抢占
##### 就绪态->运行态
- 如果一个进程已经在就绪状态等待了足够长时间
##### 阻塞态->就绪态
- 等待的事件完成后
#### 七状态模型（挂起）
- 为了缓解内存紧张，操作系统把暂时不能运行的进程换出到外存，此时进程多了两个状态：
	- 就绪挂起态：进程在外存，已具备运行条件，只需调入内存即可运行
	- 阻塞挂起态：进程在外存，仍在等待某事件发生
- 新增的转换：
	- 就绪 → 就绪挂起：内存紧张时，把就绪进程换出到外存
	- 阻塞 → 阻塞挂起：内存紧张时，把阻塞进程换出到外存
	- 就绪挂起 → 就绪：内存有空闲时，把就绪挂起进程换入内存
	- 阻塞挂起 → 就绪挂起：阻塞挂起进程等待的事件发生了
	- 阻塞挂起 → 阻塞：内存有空闲时，换入内存继续等待事件
	- 就绪挂起 → 执行态：内存有空闲且被调入内存后，直接参与调度
- 挂起态的进程不在内存中，不参与调度；只有内存中的就绪进程才能被调度
### 状态队列
- OS维护一组队列，用来表示系统中所有进程的当前状态，不同的状态对应不同的队列
- 当进程状态发生变化时，把它的PCB从一个状态队列中脱离出来，加入另外一个队列中
- ![[进程状态队列.svg]]
### 进程控制块
- PCB主要包含四个方面的信息
#### 进程标识符
- 用于唯一地标识一个进程
- 外部标识符：方便用户对进程的访问，由创建者提供，通常由字母、数字组成
- 内部标识符：方便系统对进程的使用，唯一数字标识，通常是进程的序号
#### 处理机状态
- 也称为处理机的上下文，包括通用寄存器、指令计数器、程序状态字等
#### 进程调度消息
- 进程状态
- 进程优先级
- 进程调度所需的其他信息（进程已等待CPU的时间总和、进程已执行的时间总和等）
- 事件（阻塞原因）
#### 进程控制信息
- 程序和数据的地址
- 进程同步和通信机制
- 资源清单：进程运行期间所需的全部资源
- 链接指针：指向下一个PCB的首地址
### 使用原语控制进程
- 原语：**原子操作**的函数
#### 进程的创建
1. 申请空白PCB
2. 为新进程分配所需资源
3. 初始化PCB上的内容
4. 若顺利，进入就绪态；反之，父进程进入阻塞态，新进程处于创建态
#### 进程的终止
1. 根据进程号PID，找到进程对应的PCB
2. 修改进程状态到终止态
3. 若有子进程，则也应终止
4. 将被终止进程的PCB从队列中移除
#### 进程的阻塞和唤醒
- 请求资源失败或等待事件发生时，进程转为阻塞态
- 调用wakeup原语进行唤醒：
	1. 将进程从阻塞队列移除
	2. 将PCB中的状态改为就绪
	3. 将PCB插入就绪队列
### 虚拟地址空间
- 地址空间（虚拟地址空间）中的指令地址和数据地址不是进程实际执行时的地址。
- 地址空间分为用户空间和内核空间。用户进程只能写入用户空间的程序
### 进程切换模型
-  ![[进程切换模型.svg]]
- 系统内核也在内存中，所以进程切换必然发生在**内核态**
- 进程跳转到系统内核代码，可能不发生进程的切换
- ![[进程切换模型2.svg]]
## 线程与进程间通信
### 进程间通信
#### 基本概念
- 低级通信：进程间传递少量控制信息（几个字节/一个数组）
- 高级通信：进程间传递大量数据（一个文件）
#### 共享内存
- 内存中开辟一块属于两个进程的空间
- 分为**共享数据结构**和**共享存储区**
#### 消息传递
- 消息是进程通信的基本单位，通信的数据被封装在消息中
- 进程1发送消息给操作系统，进程2通过操作系统接收消息
- 消息结构：PID、正文长度、指向正文的指针、指向下一个消息的指针
- 消息传递属于高级通信，分为直接通信方式和间接通信方式
	- 直接通信方式：指明接收进程
	- 间接通信方式：指明接收“邮箱”
#### 管道
- 管道是一种特殊的共享文件（pipe 文件），以文件系统为基础，在内存中开辟一块固定大小的缓冲区
- 写进程往管道尾部写数据，读进程从管道头部读数据，数据按 FIFO 顺序流动
- 特点：
	- **半双工**：某一时刻只能单向传输，若要双向通信需要建立两个管道
	- 管道是**固定大小的缓冲区**：管道满时写进程阻塞，管道空时读进程阻塞
	- 数据读出后即从管道中消失，不能重复读取
	- 匿名管道只能用于有亲缘关系（父子、兄弟）的进程，命名管道（FIFO）可用于任意进程
- 管道通信需要同步互斥：读写进程必须互斥地访问管道，并保证“先写后读”的顺序
#### 信号
- 用于告知进程某个事件
- 系统中有很多事件，每种信号对应一个事件
- Linux系统中 kill -l 查看所有信号
### 线程
#### 初识线程
- 线程：是进程当中的一条执行流程，让同一个进程的函数可以并发运行，就像各个进程之间并发运行一样
- 进程是资源所有权和调度/执行的单位；线程是操作系统调度的最小单位
- 线程控制块TCB：用于控制和管理线程的状态和信息
	- 主要包括：线程自身的管理信息、线程所独享的资源
	- 状态：执行态、阻塞态、就绪态
- 同一进程的各线程共享地址空间，可以直接通信，减少通信开销；线程间切换的消耗少

| 比较项 | 进程 | 线程 |
| --- | --- | --- |
| 调度 | 引入内核线程后，不再是调度的最小单位 | 是**调度**的最小单位 |
| 拥有资源 | **资源分配**的基本单位 | 线程只拥有少量资源，如寄存器和栈 |
| 并发性 | 多个进程间可以并发执行 | 一个进程的多个线程也能并发执行 |
| 切换开销 | 进程切换开销大 | 切换开销小 |
| 创建时间 | 长 | 短 |
| 终止时间 | 长 | 短 |
| 通信开销 | 需要借助内核，通信开销大 | 处于同一地址空间，可以直接通信 |
#### 线程的实现
- 本质上是创建一个TCB，包括线程标识符（TID）、线程执行状态、线程调度信息、CPU寄存器的值、栈指针
- 根据创建的位置不同，分为用户级线程和内核级线程
##### 用户级线程（ULT）
- 用户线程是一组用户级的线程库函数来完成线程的管理；用户级线程的实现与OS平台无关
- 线程阻塞会导致进程无法运行
- 线程切换代价小
- 进程的上下文切换：![[进程的上下文切换.svg]]
##### 内核支持线程（KST）
- 线程切换代价大；线程阻塞不会影响进程
##### 组合方式
- 当用户级线程需要内核服务时，就请求一个内核级线程帮忙
###### 一对一模型
- ![[一对一模型.svg]]
- 优点：允许多线程并行运行在多个处理机上
- 缺点：开销大
###### 多对一模型
- ![[多对一模型.svg]]
- 优点：开销小、效率高
- 缺点：如果一个线程在访问内核时发生阻塞，则整个进程都会被阻塞
###### 多对多模型
- ![[多对多模型.svg]]
- 优点：允许多线程并行运行在多个处理机上、开销小、效率高
## CPU调度
### 分级调度
#### 概念
- 作业：用户要求计算机完成的关于一次业务处理的全部工作
- 作业的状态分为提交、收容、执行和完成
- 典型三级调度：作业调度、交换调度、进程调度![[批处理系统的三级调度.svg]]
#### 作业调度/高级调度
- 决定后备队列中的哪几个作业调入内存，为他们创建进程，分配必要资源，并将它们放入就绪队列
- 在分时和实时系统中不设置作业调度
#### 进程调度/低级调度
- 决定就绪队列中的哪个进程应获得处理机
- 进程调度时最基本的一种调度
#### 交换调度/中级调度
- 将外存中的就绪状态或等待状态的进程调入内存，或把处于内存就绪状态或内存等待状态的进程交换到外存中。
- 被交换到外存的进程的状态为挂起态
### 调度目标与性能指标
#### 调度目标
- 资源利用率：$CPU利用率=\frac{CPU有效工作时间}{CPU有效工作时间+CPU空闲时间}$
- 公平性：使进程获得合理的CPU时间，不会发生进程饥饿现象
- 平衡性：保持不同系统资源使用的平衡性（计算型/IO型）
#### 批处理系统的目标
- 平均周转时间短：$T=T_{finish}-T_{arrive}$，$\bar T=\frac{1}{n}\sum^n_{i=1} T_i$
	- 带权周转时间：$W=\frac{T}{t_s}$，周转时间T，系统提供服务时间$t_s$
- 系统吞吐量高：单位时间内系统完成的作业数
- 处理机利用率高
#### 分时系统的目标
- 响应时间快：用户提交请求到屏幕显示结果的时间
- 均衡性：系统响应时间与用户请求的复杂性相适应
#### 等待时间
- 进程：进程在就绪队列中的时间
- 作业：从提交到被作业调度程序选中
### 调度算法
#### 先来先服务调度算法（FCFS）
- 优点：公平
- 缺点：执行时间短但后到的作业要等待较长时间
#### 短进程/作业优先算法（SPF）
- 不可抢占方式：正在运行的进程不会被新来的更短进程打断
- 可抢占方式：若新进程运行时间小于当前进程的剩余时间，则新进程抢占CPU；也称为最短剩余时间优先（SRTF）
- 优点：可抢占式SPF的平均等待/周转时间最优
- 缺点：需要知道每个作业的运行时间；对长作业不利；未考虑作业优先度
#### 优先级调度算法
- 非抢占式优先级调度算法
- 抢占式优先级调度算法：常用于实时性要求较高得到系统中
	- 静态优先级：设计依据
		- 进程类型：系统进程>用户进程；交互型进程>非交互型进程；I/O型进程>计算型进程
		- 进程对资源的需求：要求少>要求多
		- 用户要求：根据紧迫程度
	- 动态优先级
#### 高响应比优先调度算法
- $优先级=\frac{等待时间+要求服务时间}{要求服务时间}=\frac{等待时间}{要求服务时间}+1$
- 优点：这种算法不会发生饥饿现象，既符合FCFS又兼顾长短作业
#### 时间片轮转调度算法
- 将处理器使用时间划分为一个个时间片，公平分给每个就绪进程
- 时钟中断发生时，系统会修改当前进程在时间片内的剩余时间
- 适用于分时操作系统
- 时间片大小的确定：过大则退化为 FCFS；过小则切换过于频繁、开销大，通常取略大于一次典型交互所需的时间
#### 多级队列调度算法
- 将系统中的进程就绪队列拆分为若干个，不同类型的进程分配到不同的队列中，采用不同的算法
#### 多级反馈队列调度算法
- 设置多个就绪队列，并为队列设置不同的优先级（第 1 级最高，逐级降低）
- 各队列的时间片长度不同：优先级越高的队列时间片越短，越低的队列时间片越长
- 每个队列内部按 FCFS 排队
- 调度规则：
	1. 新进程进入内存后，先放入第 1 级队列的末尾，按 FCFS 等待调度
	2. 若进程在第 1 级队列的时间片内没有运行完，则被剥夺 CPU，放入第 2 级队列末尾；在第 2 级仍未完成，再降入第 3 级，依此类推
	3. 仅当第 1 级队列为空时，才调度第 2 级队列中的进程；第 2 级也为空才调度第 3 级，以此类推
	4. 若正在低级队列中运行的进程，此时有新进程进入高优先级队列，则立即被抢占，CPU 让给高优先级队列的进程，被抢占的进程放回原队列末尾
- 特点：兼顾短进程优先（短进程在高优先级队列很快完成）与 FCFS（同队列内先来先服务）；长进程逐渐降级，运行时间越长优先级越低
- 优点：不需预知进程运行时间，能较好满足各类进程的需要，是公认较好的一种调度算法
- 缺点：实现复杂；低优先级队列的进程可能长期得不到调度（饥饿）
#### 保证调度算法
- 保证每个进程获得相同的处理机时间，针对进程公平
- 功能：
	- 跟踪每个进程已经执行的处理时间
	- 计算每个进程应获得的处理机时间
	- 计算进程获得处理机时间的比率
	- 根据比率分配处理机资源
#### 公平分享调度算法
- 针对用户公平
#### 对比

| 调度算法 | 是否可抢占 | 是否会导致饥饿 | 算法考虑因素 | 优点 | 缺点 |
| --- | --- | --- | --- | --- | --- |
| 先来先服务 | 否 | 否 | 进程到达时间 | 公平，实现简单 | 不利于短作业 |
| 短进程优先 | 均可 | 是 | 进程预计进行时间 | 平均等待时间、平均周转时间最优（抢占时） | 不利于长作业，可能有饥饿现象 |
| 高响应比优先 | - | 否 | 进程预计运行时间+等待时间 | 兼顾长短作业 | 计算响应比的开销大 |
| 时间片轮转 | 可以 | 否 | 所有进程公平分时使用处理器 | 相对公平，有利于实现人机交互 | - |
| 多级反馈队列 | 是 | 是 | 较为复杂 | 公认的一种较好的进程调度算法 | 复杂 |

### 进程调度的实现
#### 调度程序
- 负责根据调度算法选中下一个进程，然后切换到目标进程的运行环境
#### 调度的时机
##### 一般情形
- 当创建新进程后，新进程与其父进程都就绪时
- 一个进程运行完毕时
- 一个进程被阻塞时
- 分时系统中，该进程时间片用完时
- 可抢占优先级调度算法中，有优先级更高的进程进入就绪队列时
- 当一个I/O中断发生时，可能会发生调度
##### 需要等待事件结束后才能调度的情形
- 在处理中断的过程中
- 原子操作过程中
#### 调度的方式
##### 非抢占式调度
- 优点：算法设计简单，调度成本低
- 缺点：仅适用于早期批处理系统
##### 抢占式调度
- 主要原则：优先权原则、短进程优先原则、时间片轮转原则
#### 闲逛进程
- 指一种没有明确工作，用于解决调度中可能发生的特殊情况的进程
## 同步与互斥
### 基本概念
#### 互斥
- 当某个进程访问某个共享资源时，若有其他进程正在访问，则必须等待其他进程释放资源后才可以访问。这种资源共享方式称为互斥共享，称进程A、B的关系为互斥关系。
#### 同步
- 多个进程间发生的事件存在某种时序关系，必须协同动作、相互配合来共同完成一个任务
#### 临界资源与临界区
- 临界资源：一次只允许一个进程使用的资源
- 临界资源的访问过程：
	- 进入区：检查资源是否正在被访问，未被访问的资源可以进入临界区并被标为正在访问。
	- 临界区：临界资源访问的那段程序
	- 退出区：清除资源正在访问临界区的标志
	- 剩余区：代码的其余部分
### 进程互斥、同步的实现
#### 临界区互斥的准则
- 空闲让进
- 忙则等待
- 有限等待
- 让权等待：进程不能进入临界区时，应立即释放处理机
#### 软件方法
- 在进入区设置并检查一些标志
##### 单标志法
- 设置一个公用整型变量turn，指示允许进入临界区的进程编号
- 进程退出临界区时将临界区的使用权赋给另一个进程
- 缺点：违背空闲让进
##### 双标志先检查法
- 设置一个布尔型数组flag[2]，用来标记各个进程想进入临界区的意愿，先检查对面，再设置自己
- 优点：不用交替进入，可连续使用
- 缺点：进程可能同时进入临界区，违背忙则等待
##### 双标志后检查法
- 设置一个布尔型数组flag[2]，用来标记各个进程想进入临界区的意愿，先设置自己再检查对面
- 缺点：可能都想进入临界区，结果都进不了，导致长期无法访问。违背了空闲让进和有限等待原则
- 优点：解决同时进入临界区的问题
##### Peterson算法
- 使用flag[]表达意愿，变量turn表示哪个进程可以进入临界区
- 优点：遵循了空闲让进、忙则等待、有限等待三个原则
- 缺点：违背让权等待准则，因为即使进程不进入临界区，也要运行while检查何时能进，占用资源
##### 对比

| 方法          | 简述                           | 缺点                     |
| ----------- | ---------------------------- | ---------------------- |
| 单标志法        | 引入 turn，循环检查直到 turn=本进程编号    | 只能交替进入，违背“空闲让进”        |
| 双标志先检查法     | 引入 flag[2]，先检查对方是否进入临界区      | 可能会同时进入，违背“忙则等待”       |
| 双标志后检查法     | 引入 flag[2]，先设置自身 flag，再检查    | 同时希望进入时，违背“有限等待”“空闲让进” |
| Peterson 算法 | 引入 turn 和 flag[2]，进入临界区前检查两次 | 违背“让权等待”               |

#### 硬件方法
##### 关中断
- 进入临界区前禁止中断，临界区后开中断，这样在临界区就无法被外部中断
- 优点：实现简单、开销小；关中断期间进程无法被切换，也不需要忙等
- 缺点：关中断权不应交给用户进程；并发环境中关中断会影响系统执行效率；不适用于多CPU系统，关中断仅限于执行该指令的处理器
##### TestAndSet 指令（TS 指令）
- 由硬件实现的原子指令，执行过程不可被中断，适用于多处理机
- 功能：读出指定标志的旧值，将该标志置为 true（上锁），并返回旧值
```c
bool TestAndSet(bool *lock) {
    bool old = *lock;
    *lock = true;
    return old;
}
```
- 使用方式（lock 初值为 false）：
```c
while (TestAndSet(&lock));  // 进入区：旧值为 true 说明已被上锁，忙等
// 临界区
lock = false;               // 退出区：解锁
```
- 优点：实现简单，适用于多处理机环境
- 缺点：不满足让权等待，等待的进程忙等占用 CPU，可能发生饥饿
##### Swap 指令（对换指令）
- 原子地交换两个字的指令，通过交换实现上锁
- 每个进程设置一个局部变量 key（初值 true），lock 初值 false：
```c
bool key = true;
do {
    Swap(&lock, &key);   // 原子交换：lock 与 key 的值互换
} while (key);           // key 仍为 true，说明 lock 原来已被占用
// 临界区
lock = false;
```
- 同样不满足让权等待，等待进程忙等
##### 互斥锁
- 用一个 lock 变量表示锁的状态，用 acquire() 加锁、release() 解锁
- 忙等版本（自旋锁）：acquire 失败时循环检测，进程不被阻塞、不切换，适用于多处理机且临界区很短的情况；单处理机上自旋会浪费 CPU
- 阻塞版本：acquire 失败时将进程加入锁的等待队列并阻塞（让权等待），release 时唤醒等待队列中的一个进程
- 互斥锁是操作系统中最基本的同步工具，只能解决互斥问题，不能直接解决同步问题
##### 硬件方法对比
| 方法 | 原子性 | 是否让权等待 | 适用范围 |
| --- | --- | --- | --- |
| 关中断 | 是 | 不需要忙等 | 仅单处理机 |
| TestAndSet | 是 | 否（忙等） | 多处理机 |
| Swap | 是 | 否（忙等） | 多处理机 |
### 信号量机制
- 信号量（Semaphore）是一个用于解决进程同步与互斥的变量，只能通过**原语**（P、V 操作）访问，以保证操作的原子性
- P 操作（wait）：申请一个资源；V 操作（signal）：释放一个资源
#### 整型信号量
- 用一个整型变量 S 表示资源数目，只能通过两个原子操作访问：
```c
void wait(int S) {
    while (S <= 0);   // 资源不足则一直循环检测（忙等）
    S--;
}
void signal(int S) {
    S++;
}
```
- 缺点：不满足让权等待，进程在 while 循环中忙等，浪费 CPU
#### 记录型信号量
- 用结构体记录资源剩余数量和等待队列，解决整型信号量的忙等问题
```c
typedef struct {
    int value;             // 资源剩余数量
    struct process *L;     // 等待队列
} semaphore;

void wait(semaphore S) {
    S.value--;
    if (S.value < 0) block(S.L);    // 资源已用完，进程自我阻塞并进入等待队列
}

void signal(semaphore S) {
    S.value++;
    if (S.value <= 0) wakeup(S.L);  // 仍有等待进程，唤醒其中一个
}
```
- 初值 = 资源的数目；`S.value < 0` 时，`|S.value|` 表示该信号量等待队列中阻塞的进程数
- 满足让权等待：进程申请不到资源时主动阻塞，释放处理机
- 记录型信号量的 value 可以取负值，这是与整型信号量在语义上的重要区别
#### 用信号量实现进程互斥
- 设置互斥信号量 mutex，初值为 1（表示临界资源只有一个）
```c
semaphore mutex = 1;

P1() {
    P(mutex);
    // 临界区
    V(mutex);
    // 剩余区
}

P2() {
    P(mutex);
    // 临界区
    V(mutex);
    // 剩余区
}
```
- 注意：mutex 的 P、V 必须成对出现在同一个进程内，P 在进入临界区之前，V 在退出临界区之后
#### 用信号量实现进程同步
- 同步信号量的初值通常为 0（表示"事件尚未发生"）
- 若要求进程 A 的语句 x 必须在进程 B 的语句 y 之前执行，则：
```c
semaphore S = 0;

A() {
    x;
    V(S);   // x 执行完，告知 B
}

B() {
    P(S);   // 等待 x 执行完
    y;
}
```
- 口诀："前 V 后 P"——前驱操作之后 V，后继操作之前 P
#### 用信号量实现前驱关系
- 前驱关系可用有向无环图（DAG）描述：为每一条前驱边设置一个信号量，初值为 0
- 前驱活动结束后对相应信号量执行 V，后继活动开始前执行 P
- 例：S1→S2、S1→S3、S2→S4、S3→S4，可设置 a=b=c=d=e=0，按图在每条边上 V/P 即可
- 多个前驱时，后继进程需要按顺序 P 各条边对应的信号量
#### 信号量集与 AND 信号量（了解）
- AND 型信号量：一次申请所有需要的资源，全部满足才分配，否则一个也不分配，从而避免多个共享资源引起的死锁
```c
Swait(S1, S2, ..., Sn) {
    while (1) {
        if (S1 >= 1 && S2 >= 1 && ... && Sn >= 1) {
            for (int i = 1; i <= n; i++) Si--;
            break;
        } else {
            // 将进程放入第一个不满足条件的 Si 的等待队列
        }
    }
}
```
- 信号量集：`Swait(S, d, t)` 表示当 S ≥ t 时一次申请 d 个资源（d 可大于 1），否则等待；`Ssignal(S, d)` 一次释放 d 个
#### 易错点
- **P 操作的顺序不能颠倒**：既有同步信号量又有互斥信号量时，必须先 P 同步信号量，再 P 互斥信号量；否则可能死锁（如缓冲区满时生产者先拿到 mutex 再等待 empty，消费者无法进入临界区取走产品）
- V 操作的顺序可以颠倒（V 不会引起阻塞），但先 V(mutex) 再 V(同步信号量) 可以减少其他进程的等待时间
- 同一信号量的 P、V 必须配对，且一般 P 在前、V 在后；互斥信号量的 P、V 在同一进程内配对，同步信号量的 P、V 在不同进程间配对
- 多个信号量时，P 的顺序不当会引起死锁；V 的顺序不影响结果的正确性
- 信号量的初值：互斥信号量为 1；同步信号量为 0（或所需资源的数目）
### 管程
#### 定义与组成
- 背景：信号量的 P、V 操作分散在各进程中，编程困难、容易出错（漏写 V、P 顺序错误等）
- 管程（Monitor）是一种高级同步机制，把共享数据结构及对其操作的一组过程封装在一起，任一时刻仅允许一个进程在管程内执行某个内部过程
- 组成：
	1. 管程的名称
	2. 局部于管程的共享数据结构说明
	3. 对该数据结构进行操作的一组过程（函数）
	4. 对局部于管程的共享数据设置初值的语句
- 基本特征：
	1. 局部于管程的数据只能被局部于管程的过程访问
	2. 一个进程只有通过调用管程内的过程才能进入管程访问共享数据
	3. 每次仅允许一个进程在管程内执行某个内部过程，互斥由编译器负责实现，进程无须自己实现互斥
#### 条件变量
- 条件变量用于解决管程内的同步问题：当进程在管程内发现某条件不满足时，需要等待
- `x.wait()`：调用进程阻塞，释放管程，插入 x 的等待队列
- `x.signal()`：唤醒 x 等待队列中的一个进程；若没有等待进程，则什么也不做（信号丢失）
- 条件变量与信号量的区别：条件变量没有值，wait 必然阻塞；信号量有值，P 操作可能不阻塞；signal 无等待进程时信号丢失，而 V 操作会使信号量的值加一
#### 用管程实现生产者-消费者
```c
monitor ProducerConsumer {
    condition full, empty;
    int count = 0;

    void insert(Item item) {
        if (count == N) full.wait();   // 缓冲区满，等待
        count++;
        将 item 放入缓冲区;
        if (count == 1) empty.signal(); // 由空变非空，唤醒消费者
    }

    Item remove() {
        if (count == 0) empty.wait();   // 缓冲区空，等待
        count--;
        Item item = 从缓冲区取出;
        if (count == N - 1) full.signal(); // 由满变不满，唤醒生产者
        return item;
    }
}
```
#### 管程与信号量的比较
| 比较项 | 信号量 | 管程 |
| --- | --- | --- |
| 同步方式 | 分散在各进程中，由程序员保证 P/V 配对 | 封装在管程内部，由编译器/语言机制保证互斥 |
| 易用性 | 易出错（漏写、顺序错误） | 不易出错，可读性好 |
| 实现层次 | 原语，可由硬件或软件实现 | 语言级同步机制，通常基于信号量实现 |
| 支持 | 互斥与同步 | 互斥由管程保证，同步由条件变量实现 |
- Java 中用 `synchronized` 修饰的方法或代码块即管程的实现；`wait()`、`notify()`、`notifyAll()` 对应条件变量的操作
### 经典同步问题
#### 生产者-消费者问题
- 问题描述：一组生产者进程和一组消费者进程共享一个初始为空、大小为 n 的缓冲区；缓冲区满时生产者必须等待，缓冲区空时消费者必须等待；缓冲区是临界资源，各进程必须互斥访问
- 信号量设置：mutex=1（互斥访问缓冲区）、empty=n（空缓冲区数）、full=0（产品数）
- ![[生产者消费者PV.svg]]
```c
semaphore mutex = 1;
semaphore empty = n;
semaphore full = 0;

producer() {
    while (1) {
        生产一个产品;
        P(empty);      // 申请一个空缓冲区
        P(mutex);
        将产品放入缓冲区;
        V(mutex);
        V(full);       // 产品数加一
    }
}

consumer() {
    while (1) {
        P(full);       // 申请一个产品
        P(mutex);
        从缓冲区取出一个产品;
        V(mutex);
        V(empty);      // 空缓冲区数加一
        消费该产品;
    }
}
```
- 关系分析：生产者与消费者之间是同步关系（empty、full），生产者之间、消费者之间是互斥关系（mutex）
- 易错：若将 P(mutex) 写在 P(empty) 之前，缓冲区满时生产者阻塞在 mutex 上，消费者无法进入缓冲区取产品，导致死锁
- 若缓冲区大小为 1，则 empty 与 full 已能保证互斥，mutex 可以省略
#### 多生产者-多消费者问题
- 例：盘子只能放一个水果，爸爸放苹果、妈妈放橘子，儿子吃苹果、女儿吃橘子
```c
semaphore plate = 1;    // 盘子容量
semaphore apple = 0;
semaphore orange = 0;

dad()       { 准备苹果; P(plate); 放苹果; V(apple); }
mom()       { 准备橘子; P(plate); 放橘子; V(orange); }
son()       { P(apple); 取苹果; V(plate); 吃苹果; }
daughter()  { P(orange); 取橘子; V(plate); 吃橘子; }
```
- 盘子容量为 1 时，plate 与 apple/orange 已保证互斥，无需额外的 mutex；若容量大于 1，则必须设置 mutex 保护盘子
- 分析思路：先找出有几对同步关系（苹果、橘子），再判断缓冲区容量是否大于 1，决定是否需要互斥信号量
#### 读者-写者问题
- 规则：允许多个读者同时读；写者与其他任何进程（读者或写者）互斥；写者之间互斥
- 读者优先（读者源源不断时写者可能饥饿）：
```c
semaphore rw = 1;     // 读写互斥、写写互斥
semaphore mutex = 1;  // 保护 count 变量
int count = 0;        // 当前读者数

reader() {
    P(mutex);
    if (count == 0) P(rw);  // 第一个读者负责加锁
    count++;
    V(mutex);
    读;
    P(mutex);
    count--;
    if (count == 0) V(rw);  // 最后一个读者负责解锁
    V(mutex);
}

writer() {
    P(rw);
    写;
    V(rw);
}
```
- 写者优先：增加信号量 w=1，读者进入前先 P(w)，写者到来时 P(w) 阻止后续读者进入，从而实现写者优先
```c
semaphore rw = 1, mutex = 1, w = 1;
int count = 0;

reader() {
    P(w);            // 有写者正在等待或正在写，则读者等待
    P(mutex);
    if (count == 0) P(rw);
    count++;
    V(mutex);
    V(w);
    读;
    P(mutex);
    count--;
    if (count == 0) V(rw);
    V(mutex);
}

writer() {
    P(w);
    P(rw);
    写;
    V(rw);
    V(w);
}
```
- 应用：数据库的读写锁、文件的读写共享
#### 哲学家进餐问题
- 问题描述：5 名哲学家围坐圆桌，每两人之间放一根筷子；哲学家交替思考与进餐，进餐需要同时拿起左右两根筷子
- 朴素方案：每人先 P(左筷) 再 P(右筷)——若 5 人同时拿起左手筷子，则都在等待右手筷子，形成循环等待而死锁
- 解决方法：
	1. 至多允许 4 名哲学家同时进餐：设置信号量 count=4，进餐前 P(count)
	2. 仅当左右两根筷子都可用时才允许拿起：用 AND 信号量，或设置 mutex 互斥地一次拿起两根
	3. 奇数号哲学家先拿左手、偶数号先拿右手：破坏循环等待条件
	4. 仅当哲学家左右两根筷子都可用时才允许进餐（可能仍不够公平，需配合其他策略）
```c
// 方案 3：奇数号先左后右，偶数号先右后左
philosopher(int i) {
    while (1) {
        思考;
        if (i % 2 == 0) { P(chopstick[i]); P(chopstick[(i+1)%5]); }
        else            { P(chopstick[(i+1)%5]); P(chopstick[i]); }
        进餐;
        V(chopstick[i]); V(chopstick[(i+1)%5]);
    }
}
```
#### 吸烟者问题（了解）
- 三个吸烟者分别拥有烟草、纸、火柴中的一种（数量无限），供应者每次随机放两种材料在桌上，拥有剩下那种材料的吸烟者卷烟并抽烟，抽完通知供应者继续
- 信号量：offer1、offer2、offer3（分别表示桌上材料组合，初值 0）、finish（表示抽完，初值 0）
- 供应者循环轮流提供三种组合，用 V(offeri) 通知对应吸烟者；吸烟者 P(offeri) 后卷烟，抽完 V(finish)；供应者每次提供前 P(finish) 等待上一次抽完
- 该问题本质是"可生产多种产品、但每次只能消费一个"的生产者-消费者问题
## 死锁
### 死锁的概念
- 死锁：多个进程因竞争资源而造成的一种僵局，若无外力作用，这些进程都将无法向前推进
- 死锁是进程并发执行中资源竞争的一种极端情况，系统中有多个进程因争夺资源而互相等待
- 产生死锁的根源：系统资源不足、进程推进顺序不合理
### 死锁、饥饿与死循环
| 概念 | 含义 | 区别 |
| --- | --- | --- |
| 死锁 | 多个进程互相等待对方持有的资源，都无法推进 | 至少两个进程，且存在循环等待；不剥夺则永远无法解除 |
| 饥饿 | 某进程因长期得不到所需资源而无法推进 | 可能只有一个进程，原因是分配策略不公平；改变策略后可能解除 |
| 死循环 | 程序逻辑错误导致循环无法结束 | 进程一直占用 CPU，可通过杀死进程或中断解决 |
### 死锁产生的必要条件
- 四个条件同时满足才可能发生死锁：
	1. 互斥条件：资源一次只能被一个进程使用
	2. 不剥夺条件：进程已获得的资源在未使用完之前不能被其他进程强行夺走，只能由占有者主动释放
	3. 请求并保持条件：进程已经保持了至少一个资源，但又提出新的资源请求，而该资源已被其他进程占有，此时请求进程阻塞，但又对自己已获得的资源保持不放
	4. 循环等待条件：存在一个进程资源的循环等待链，链中每个进程已获得的资源同时被链中下一个进程所请求
- 注意：循环等待只是死锁的必要条件，不是充分条件（资源分配图中存在环且每类资源只有一个实例时才一定死锁）
### 死锁的处理策略
| 策略 | 时机 | 做法 | 特点 |
| --- | --- | --- | --- |
| 死锁预防 | 死锁发生前 | 破坏四个必要条件之一 | 静态策略，实现简单，但资源利用率低 |
| 死锁避免 | 分配资源前 | 判断分配后系统是否处于安全状态（银行家算法） | 动态策略，资源利用率较高，但需预知最大需求 |
| 死锁检测与解除 | 死锁发生后 | 检测到死锁后撤销进程或剥夺资源 | 不限制分配，但检测与解除的代价大 |
- 不允许死锁发生：预防（静态）、避免（动态）
- 允许死锁发生：检测与解除
### 死锁预防
- 破坏互斥条件：用 SPOOLing 技术把独占设备改造成共享设备（如共享打印机）；但很多资源本身就不能被共享（如临界区），一般不现实
- 破坏不剥夺条件：进程请求新资源得不到满足时，必须释放已占有的资源；或由系统强行剥夺（剥夺后需回滚，实现复杂、开销大）
- 破坏请求并保持条件：进程运行前一次性申请全部所需资源（简单，但资源利用率低，可能饥饿）；或申请新资源前先释放已有资源，之后重新申请
- 破坏循环等待条件：采用资源顺序分配法，给每类资源编号，进程只能按编号递增的顺序申请资源（实现简单，但限制编程、可能浪费资源）
### 死锁避免
#### 安全状态与安全序列
- 安全状态：系统能按某种进程顺序（安全序列）为每个进程分配其所需资源，直至所有进程都能顺利完成
- 若系统不存在安全序列，则处于不安全状态；不安全状态不一定会死锁，但死锁一定发生在不安全状态
- 只要系统处于安全状态，就能避免死锁
#### 银行家算法的数据结构
- 设系统中有 n 个进程、m 类资源：
	- Available[m]：每类资源的可用数目
	- Max[n][m]：每个进程对每类资源的最大需求
	- Allocation[n][m]：每个进程已获得的每类资源数目
	- Need[n][m]：每个进程还需要的资源数目，Need = Max − Allocation
	- Request_i[m]：进程 Pi 本次的请求向量
#### 银行家算法步骤
1. 检查 Request_i ≤ Need_i，否则认为出错（请求量超过其最大需求）
2. 检查 Request_i ≤ Available，否则表示资源不足，Pi 必须等待
3. 试探性分配：Available = Available − Request_i；Allocation_i = Allocation_i + Request_i；Need_i = Need_i − Request_i
4. 执行安全性算法：若此次分配后系统处于安全状态，则正式分配；否则撤销本次试探分配，让 Pi 等待
#### 安全性算法
1. 设置工作向量 Work = Available，Finish[i] = false
2. 从进程集合中找到一个满足 Finish[i] = false 且 Need_i ≤ Work 的进程；若找到，则假设它完成并释放资源：Work = Work + Allocation_i，Finish[i] = true，重复此步
3. 若所有进程的 Finish 均为 true，则系统处于安全状态（按找到的顺序即安全序列）；否则处于不安全状态
#### 例题
- 系统有 A、B、C 三类资源，Available = (3, 3, 2)，各进程的 Max 与 Allocation 如下：

| 进程 | Max (A,B,C) | Allocation (A,B,C) | Need (A,B,C) |
| --- | --- | --- | --- |
| P0 | 7, 5, 3 | 0, 1, 0 | 7, 4, 3 |
| P1 | 3, 2, 2 | 2, 0, 0 | 1, 2, 2 |
| P2 | 9, 0, 2 | 3, 0, 2 | 6, 0, 0 |
| P3 | 2, 2, 2 | 2, 1, 1 | 0, 1, 1 |
| P4 | 4, 3, 3 | 0, 0, 2 | 4, 3, 1 |
- 安全性检查：Work=(3,3,2) → P1（Need≤Work）完成后 Work=(5,3,2) → P3 完成后 Work=(7,4,3) → P4 完成后 Work=(7,4,5) → P2 完成后 Work=(10,4,7) → P0 完成
- 故存在安全序列 <P1, P3, P4, P2, P0>，系统处于安全状态
- 若此时 P1 请求 (1,0,2)：Request ≤ Need、Request ≤ Available，试探分配后 Available=(2,3,0)，P1 的 Allocation=(3,0,2)、Need=(0,2,0)；按安全性算法仍可找到安全序列，故可以分配
#### 银行家算法的特点
- 优点：资源利用率较高，比死锁预防的限制少
- 缺点：需要预知每个进程的最大资源需求；进程不可剥夺；算法本身有一定开销；实际系统中难以获得 Max 的准确值

#### 死锁定理
- 化简方法：找到一个既不阻塞又非孤立的进程结点（其请求的每类资源都至少有一个空闲实例，或请求的资源已全部分配给它），消去它的所有请求边和分配边，使之成为孤立结点；重复此过程
- 死锁定理：系统处于死锁状态 ⟺ 该状态的资源分配图不可完全简化
#### 死锁检测算法
- 类似银行家算法的安全性检查：用 Available、Allocation、Request 判断能否找到一个可完成的进程，直到所有进程都能完成
- 检测的时机与频率：死锁发生概率越高、检测越频繁，CPU 利用率越低；通常根据 CPU 利用率和进程数决定何时检测
### 死锁解除
- 资源剥夺法：挂起某些死锁进程，抢占其资源分配给其他死锁进程；应防止被挂起的进程长期得不到资源而饥饿
- 撤销进程法：强制撤销部分甚至全部死锁进程，并剥夺其资源；撤销代价与进程的重要性和运行代价有关
- 进程回退法：让一个或多个进程回退到足以避免死锁的状态；需要系统记录进程的历史信息并设置还原点

# 第三章 内存管理
## 内存管理基础
### 内存管理的功能
- 内存：存放程序和数据，CPU 可直接访问；内存以字节为单位编址
- 内存管理的功能：
	1. 内存空间的分配与回收
	2. 地址转换（逻辑地址 → 物理地址）
	3. 内存空间的扩充（虚拟内存）
	4. 内存共享
	5. 存储保护
- 程序运行的基本过程：编译 → 链接 → 装入
### 程序的链接
- 静态链接：程序运行前，将所有目标模块及所需的库函数链接成一个完整的可执行文件，之后不再拆开
- 装入时动态链接：将各目标模块装入内存时，边装入边链接；便于修改和更新，便于实现共享
- 运行时动态链接：程序执行中需要某个目标模块时才将其装入并链接；加快装入过程，节省内存
### 程序的装入
- 绝对装入：编译时产生绝对地址（物理地址），只适用于单道程序环境，装入时不需要修改地址
- 可重定位装入（静态重定位）：装入时根据内存实际情况一次性把逻辑地址转换为物理地址；程序运行期间不能移动，也不能申请新的内存
- 动态运行时装入（动态重定位）：装入后地址仍为逻辑地址，程序运行时由重定位寄存器完成地址转换；程序可在内存中移动，便于共享和内存紧凑
### 逻辑地址与物理地址
- 逻辑地址（相对地址）：目标代码中的地址，各模块从 0 开始编址
- 物理地址（绝对地址）：内存单元的实际地址
- 地址重定位（地址变换）：把逻辑地址转换为物理地址的过程
### 内存保护
- 方法一：设置上、下限寄存器，分别存放进程的上、下限地址；访问越界时产生越界中断
- 方法二：基址寄存器 + 限长寄存器；物理地址 = 基址 + 逻辑地址，逻辑地址 ≥ 限长则越界
- 越界检查由硬件完成，越界产生内中断（异常），交由操作系统处理
### 内存共享
- 可重入代码（纯代码）可被多个进程共享：允许多个进程同时访问，且执行中不修改自身
- 不可重入代码（含全局变量、自修改代码）不能被共享，每个进程需要私有副本
- 分页系统中的共享：不同进程的页表项指向同一物理块
### 覆盖与交换
- 覆盖（Overlay）：同一程序内部，把用户空间分为固定区和若干覆盖区；将程序按模块划分，不用的模块放在外存，需要时调入覆盖；覆盖结构由程序员声明；用于早期内存不足的系统
- 交换（Swapping）：把暂时不能运行的进程整体换出到外存，把已具备运行条件的进程换入内存；由中级调度（交换调度）负责
- 区别：覆盖发生在同一进程内部，交换发生在不同进程之间；覆盖不需要外存，交换需要交换区
## 连续分配管理方式
- 连续分配：为进程分配一个连续的内存空间
### 单一连续分配
- 内存分为系统区和用户区，用户区只能装入一道程序
- 优点：实现简单、无外部碎片、开销小
- 缺点：只能单用户单任务；有内部碎片；内存利用率低；无存储保护
### 固定分区分配
- 将用户区划分为若干固定大小的分区，每个分区只装入一道作业
- 分区大小可以相等，也可以不等；用分区说明表记录分区号、大小、起始地址和状态
- 优点：实现简单，无外部碎片
- 缺点：有内部碎片；大作业可能无法装入；内存利用率低
### 动态分区分配
- 不预先划分分区，进程装入时根据其大小从空闲分区中划分
- 数据结构：空闲分区表（分区号、起始地址、大小、状态）、空闲分区链（前向/后向指针）
- 优点：无内部碎片，内存利用率高
- 缺点：会产生外部碎片；需要紧凑（拼接）技术，代价大
- 分配过程：按算法找到满足大小的空闲分区；若剩余部分大于最小可分配块，则把剩余部分留在空闲表/链中，否则整块分配
### 动态分区分配算法
- 首次适应（First Fit）：空闲分区按地址递增排列，从低地址开始查找，找到第一个满足大小的分区
	- 优点：综合性能最好；算法简单；优先使用低地址空间，保留高地址的大分区
	- 缺点：低地址部分被不断划分，留下许多难以利用的小碎片
- 最佳适应（Best Fit）：空闲分区按容量递增排列，找到第一个满足大小的分区（即最小的可用分区）
	- 优点：尽量保留大的空闲分区，以满足大作业的需求
	- 缺点：会产生大量难以利用的外部碎片；每次都要从最小的分区开始查找，算法开销大
- 最坏适应（Worst Fit）：空闲分区按容量递减排列，每次都选择最大的空闲分区
	- 优点：分配后剩余分区仍较大，便于后续使用
	- 缺点：大分区很快被用完，缺乏大分区；算法开销大
- 邻近适应（Next Fit）：从上次查找结束的位置开始继续查找，到达末尾后回到开头
	- 优点：不必每次都从低地址开始查找，空闲分区分布更均匀
	- 缺点：高地址的大分区也会被很快用完，缺乏大分区
- 对比：

| 算法 | 空闲分区排列方式 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 首次适应 | 按地址递增 | 综合性能最好，保留高地址大分区 | 低地址产生大量小碎片 |
| 最佳适应 | 按容量递增 | 保留大分区 | 产生大量外部碎片，开销大 |
| 最坏适应 | 按容量递减 | 剩余分区较大 | 缺乏大分区，开销大 |
| 邻近适应 | 按地址递增，从上次位置开始 | 分配均匀 | 缺乏大分区 |
### 动态分区的回收
- 回收区与空闲分区相邻的四种情况：
	1. 回收区前后都空闲：将三块合并，修改前一块的大小，删除后一块的表项
	2. 仅前一块空闲：合并到前一块，修改前一块的大小
	3. 仅后一块空闲：合并到后一块，修改后一块的起始地址和大小
	4. 前后都不空闲：为回收区新建一个空闲分区表项（或插入空闲链）
### 内部碎片与外部碎片
- 内部碎片：分配给进程的内存区域中未被利用的部分；固定分区、分页会产生内部碎片
- 外部碎片：内存中太小而无法分配给进程的空闲区域；动态分区、分段会产生外部碎片
- 紧凑（Compaction）：移动内存中的进程，使分散的小空闲区合并成一个大空闲区；需要动态重定位支持，开销大
## 基本分页存储管理
### 分页的基本概念
- 将内存空间划分为大小相等的块，称为页框（物理块、页帧），从 0 开始编号
- 将进程的逻辑地址空间划分为大小相等的页（页面），从 0 开始编号
- 页的大小为 2 的整数次幂（通常为 4KB），页框大小与页大小相等
- 进程的页可以离散地装入内存中不相邻的页框，用页表记录页号到页框号的映射
- 优点：无外部碎片，只有内部碎片（最后一页可能装不满），内存利用率高，便于共享
- 缺点：需要页表，地址变换需要访问内存，开销增大
### 逻辑地址结构
- 逻辑地址 A 分为页号 P 和页内偏移 W 两部分
- 设页面大小为 L，则 P = ⌊A / L⌋，W = A mod L
- 页内偏移位数 = log₂L；页号位数 = 逻辑地址位数 − 页内偏移位数
- 例：32 位逻辑地址、页大小 4KB，则页内偏移 12 位、页号 20 位
### 页表
- 页表记录进程的每个页对应的物理块号，一个进程一张页表
- 页表项通常只存放物理块号（页号隐含在页表项的顺序中）
- 页表寄存器（PTR）存放页表始址 F 和页表长度 M（页表项个数）
- 页表一般存放在内存中，进程切换时更新 PTR
### 基本地址变换机构
1. 从逻辑地址中分离出页号 P 和页内偏移 W
2. 若 P ≥ M（页表长度），产生越界中断
3. 计算页表项地址 = F + P × 页表项长度，读出物理块号 b
4. 物理地址 = b × L + W
- 每次访问一个逻辑地址需要两次访问内存：一次查页表、一次取数据
- ![[分页地址变换.svg]]
### 具有快表的地址变换机构
- 快表（TLB， Translation Lookaside Buffer）：一种相联存储器，存放最近访问过的页表项副本，利用程序的局部性原理
- 地址变换：先查 TLB，命中则直接得到物理块号；未命中则查内存中的页表，并把该页表项装入 TLB
- 若无 TLB，访问一个逻辑地址需两次访存；TLB 命中时只需一次访存
- 有效访问时间：设 TLB 命中率为 a，TLB 访问时间为 t，内存访问时间为 m，则
	- $EAT = a(t + m) + (1 - a)(t + 2m)$
- TLB 与 Cache 的区别：TLB 存放页表项，Cache 存放数据/指令
### 两级页表与多级页表
- 问题：页表项数多时，页表本身很大，且要求连续存放，难以满足
- 两级页表：将页表再分页，并为这些页表页建立页目录（顶级页表）
	- 逻辑地址结构：一级页号（页目录索引）+ 二级页号（页表索引）+ 页内偏移
	- 无 TLB 时访问一个逻辑地址需要三次访存：查页目录、查页表、访问数据
- 多级页表：n 级页表在无 TLB 时需要 n + 1 次访存；级数越多，地址变换越慢，但可节省页表的存储空间，且各级页表不必连续存放
- 常考：页目录项数 = 2^(页号位数)，各级页表的大小与页大小的关系
### 分页的计算
- 页表项数 = 2^(逻辑地址位数 − 页内偏移位数)
- 页表大小 = 页表项数 × 页表项长度
- 页表占用的页框数 = ⌈页表大小 / 页大小⌉
- 页框数 = 内存大小 / 页大小
- 例：32 位逻辑地址、页大小 4KB、页表项 4B，则页表项数为 2²⁰ = 1M，页表大小为 4MB，占用 1024 个页框
## 基本分段存储管理
### 分段
- 按程序的逻辑功能划分段，如代码段、数据段、栈段，每段从 0 开始编址
- 段长不固定，由程序逻辑决定；各段在内存中可以离散存放
- 逻辑地址：段号 S + 段内偏移 W；段号位数决定一个进程最多有多少段，段内偏移位数决定最大段长
- 优点：便于共享、便于保护、便于动态增长、便于动态链接；无内部碎片
- 缺点：有外部碎片；地址变换需两次访存；内存分配复杂
### 段表与地址变换
- 每个进程一张段表，每个段对应一个段表项：段号、段长、基址
- 段表寄存器存放段表始址和段表长度
1. 从逻辑地址中取出段号 S 和段内偏移 W
2. 若 S ≥ 段表长度，产生越界中断
3. 查段表得到该段的基址和段长
4. 若 W ≥ 段长，产生越界中断（段内偏移越界）
5. 物理地址 = 基址 + W
- 无快表时需要两次访存（查段表、访问数据）
### 分页与分段的对比
| 对比项   | 分页               | 分段                |
| ----- | ---------------- | ----------------- |
| 划分单位  | 物理单位，页大小由系统决定且固定 | 逻辑单位，段长由程序逻辑决定且可变 |
| 地址空间  | 一维（一个逻辑地址）       | 二维（段号 + 段内偏移）     |
| 碎片    | 有内部碎片，无外部碎片      | 有外部碎片，无内部碎片       |
| 共享与保护 | 不便于共享和保护         | 便于共享和保护           |
| 对用户   | 透明               | 可见                |
| 内存分配  | 简单（按页框分配）        | 复杂（按段长分配）         |
### 段页式管理
- 先将用户程序分段，再将每段分页；内存按页框划分
- 每个进程一张段表，每个段一张页表；段表项：段号、页表长度、页表始址
- 逻辑地址：段号 S + 页号 P + 页内偏移 W
- 地址变换：查段表得到该段页表始址 → 查页表得到物理块号 → 物理地址 = 块号 × 页大小 + 页内偏移
- 无 TLB 时需要三次访存（段表、页表、数据）
- 优点：兼具分段的逻辑优点（便于共享和保护）和分页的物理优点（无外部碎片）
- 缺点：地址变换开销大，需要更多的硬件支持
## 虚拟内存
### 传统存储管理方式的特征与缺点
- 一次性：作业必须一次性全部装入内存后才能开始运行
- 驻留性：作业装入内存后一直驻留，直到运行结束
- 缺点：大作业无法运行；内存中同时驻留的作业数受限，多道程序度低；内存利用率低
### 局部性原理
- 时间局部性：刚被访问的指令或数据很可能在不久的将来再次被访问（如循环）
- 空间局部性：刚被访问的地址附近的地址很可能在不久的将来被访问（如数组、顺序执行的指令）
- 局部性原理是虚拟内存能够有效工作的基础
### 虚拟内存的定义与特征
- 虚拟内存：只把作业的一部分装入内存便可运行，运行过程中根据需要调入其他部分；内存空间不足时，把暂时不用的部分换出到外存
- 特征：
	1. 多次性：作业在运行过程中分多次调入内存
	2. 对换性：作业运行时可换入换出
	3. 虚拟性：从逻辑上扩充内存容量，使用户看到的内存容量远大于实际容量
- 实现方式：请求分页、请求分段、请求段页式
- 需要的支持：页表机制（增加状态位、访问字段、修改位、外存地址）、缺页中断机构、地址变换机构
- 虚拟内存的最大容量由 CPU 的寻址范围（地址结构）决定；实际容量 = min(内存容量 + 外存容量, CPU 寻址范围)
### 请求分页管理
- 页表项在基本分页的基础上增加：
	- 状态位 P：该页是否已调入内存
	- 访问字段 A：记录本页被访问的次数或最近一次访问的时间，供置换算法使用
	- 修改位 M（脏位）：该页调入内存后是否被修改过，决定换出时是否需要写回外存
	- 外存地址：该页在外存中的位置
- 优点：内存利用率高，能运行比内存大的程序；缺点：地址变换开销大，可能产生抖动
### 缺页中断
- 访问的页不在内存时产生缺页中断，由操作系统负责把所缺的页调入内存
- 缺页中断属于内中断（故障 fault），处理后返回到产生缺页的指令重新执行
- 一条指令的执行期间可能产生多次缺页中断（如指令跨页、操作数跨页）
- 缺页中断与一般中断的区别：缺页中断在指令执行期间产生和处理，一般中断在一条指令执行结束后检查
- ![[缺页中断处理.svg]]
### 请求分页的地址变换
1. 查 TLB，命中则直接得到物理块号并访问内存
2. TLB 未命中，查内存中的页表
3. 页表项状态位为 1（页在内存）：得到物理块号，更新 TLB，访问内存
4. 页表项状态位为 0（页不在内存）：产生缺页中断，由操作系统调页
	- 内存中有空闲页框则直接装入
	- 没有空闲页框则按置换算法选择一页换出（若被修改过则写回外存），再装入所缺的页
	- 更新页表和 TLB，重新执行被中断的指令
### 页面置换算法
- 最佳置换算法（OPT）：淘汰以后永不使用或在最长时间内不再被访问的页面；缺页率最低，但无法预知未来，不能实现，可作为衡量其他算法的标准
- 先进先出算法（FIFO）：淘汰最先进入内存的页面；实现简单；存在 Belady 异常（分配的页框数增加，缺页次数反而增加）
- 最近最久未使用算法（LRU）：淘汰最近最长时间未被访问的页面；性能接近 OPT；需要硬件支持（寄存器记录访问时间或栈），开销大
- 时钟置换算法（CLOCK / NRU）：将页面组织成循环队列，设置访问位；扫描到访问位为 1 的页面则置 0 并跳过，访问位为 0 则淘汰；是 LRU 的近似，开销小
- 改进型 CLOCK 算法：同时考虑访问位 A 和修改位 M，按 (A, M) 的优先级扫描：
	1. 第一轮：找 (0, 0)，不改也不访问，直接淘汰
	2. 第二轮：找 (0, 1)，访问位为 0 但被修改过，淘汰时需写回外存
	3. 第三轮：扫描过程中把访问位清 0，重复第一轮
	4. 第四轮：重复第二轮
	- 最多扫描四轮；优先淘汰未被修改的页面，可减少 I/O 次数
- 页面缓冲算法：设置空闲页面链表和已修改页面链表，换出的页面暂存在链表中，减少换入换出的开销
### 页面置换例题
- 引用串：7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2, 0, 1, 7, 0, 1；页框数为 3
- FIFO：缺页 15 次；LRU：缺页 12 次；OPT：缺页 9 次
- 结论：页框数增加时，OPT 和 LRU 的缺页次数不会增加；FIFO 可能出现 Belady 异常
### 页面分配策略
- 驻留集：分配给进程的物理页框的集合
- 分配方式：
	1. 固定分配局部置换：为每个进程分配固定数目的页框，缺页时只在本进程的页面中置换
	2. 可变分配全局置换：进程的页框数可变，缺页时从系统空闲页框链表中取一个分配给该进程；可能把其他进程的页框"抢"走
	3. 可变分配局部置换：页框数可变，但缺页时只在本进程的页面中置换；根据缺页率动态调整页框数
- 调入页面的时机：预调页（运行前或换入时一次调入若干页）、请求调页（运行时缺页才调入）
- 从何处调入：
	- 对换区足够大：全部从对换区调入（速度快）
	- 对换区不够大：不会修改的页从文件区调入，可能被修改的页从对换区调入
- 进程在运行前不一定全部装入，首次调入时采用预调页；运行中采用请求调页
### 抖动与工作集
- 抖动（颠簸）：刚被换出的页很快又要访问，刚换入的页很快又要换出，系统频繁缺页，CPU 利用率急剧下降
- 原因：分配给进程的物理页框数少于其工作集大小
- 工作集：在某段时间间隔 Δ 内，进程实际访问页面的集合；工作集大小与窗口大小 Δ 有关，Δ 过小则不能包含全部活跃页面，Δ 过大则失去意义
- 预防抖动：按工作集大小分配页框（工作集模型）；缺页率控制（PFF）；挂起部分进程
- 常考：CPU 利用率随多道程序度增加先升后降，下降到很低时说明发生了抖动
### 内存映射文件
- 将磁盘上的文件映射到进程的虚拟地址空间，进程像访问内存一样访问文件
- 采用按需调页：访问映射区时产生缺页，由操作系统从文件调入相应页
- 优点：方便、高效（减少 read/write 系统调用）；可实现共享内存（多个进程映射同一文件）
### 虚拟内存与请求分页的常考计算
- 有效访问时间（含缺页率）：设缺页率为 p，则
	- $EAT = (1 - p) \times 访问内存时间 + p \times 缺页处理时间$
- 缺页处理时间包括：缺页中断处理、磁盘寻道与传输、更新页表等，通常远大于内存访问时间

# 第四章 文件管理
## 文件系统基础
### 文件的概念
- 文件：以计算机硬盘为载体的存储在计算机上的信息集合，是操作系统对磁盘上数据的抽象
- 文件系统：操作系统用于管理文件的一组数据结构与算法，负责文件的组织、存储、检索、共享和保护
- 文件系统提供统一的逻辑视图，屏蔽底层存储设备的差异
### 文件的属性
- 名称：文件名，用户可读，同一目录下唯一
- 标识符：系统内部使用的唯一标识（如 inode 号），用户不可见
- 类型：普通文件、目录文件、设备文件、链接文件等
- 位置：文件在外存中的物理位置
- 大小：文件当前大小、可允许的最大大小
- 保护：文件的访问权限（读、写、执行）
- 时间：创建时间、最后修改时间、最后访问时间
- 所有者：文件的属主与所属用户组
### 文件的基本操作
- 创建（create）：找到外存空间，建立目录项与 FCB
- 删除（delete）：释放文件占用的外存空间，删除目录项
- 打开（open）：将文件的 FCB 从外存调入内存的系统打开文件表，返回文件描述符（文件句柄）
- 关闭（close）：从系统打开文件表中删除对应表项，释放相关的内存资源
- 读（read）：从文件当前位置读取数据，读指针自动后移
- 写（write）：向文件当前位置写入数据，写指针自动后移
- 定位（seek）：将文件的读写指针移动到指定位置，支持随机访问
- 截断（truncate）：清空文件内容但保留文件属性
- 常考：打开文件时只将 FCB 调入内存，而不是把文件内容全部读入内存
### 打开文件表
- 系统打开文件表（全局）：整个系统一张，记录所有被打开文件的 FCB 副本、打开计数器 open count
- 进程打开文件表：每个进程一张，记录进程打开的文件及其读写指针，表项通过指针指向系统打开文件表中的表项
- 文件描述符（文件句柄）：进程打开文件表的下标，进程用它来标识打开的文件
- 多个进程可同时打开同一文件：系统打开文件表只有一份，但每个进程的打开文件表各有一项，各自维护读写指针
### 文件的基本结构
- 文件在逻辑上可分为：数据项 → 记录 → 文件
- 数据项：最低级的数据组织形式，分为基本数据项（一个字段）和组合数据项（若干字段组成）
- 记录：一组相关数据项的集合，用于描述一个对象在某方面的属性
- 文件：由创建者定义的、具有文件名的一组相关元素的集合
## 文件的逻辑结构
### 无结构文件
- 又称流式文件，文件内部按字节流排列，不划分记录
- 如源程序、可执行文件、文本文件；管理简单，是大多数系统采用的方式
### 有结构文件
- 又称记录式文件，由若干记录组成，记录可以是定长的或变长的
- 按记录的组织方式分为：顺序文件、索引文件、索引顺序文件、直接（散列）文件
### 顺序文件
- 记录顺序排列，通常按存入顺序（串结构）或按关键字排序（顺序结构）排列
- 串结构：记录按存入时间排序，检索只能顺序查找，效率低
- 顺序结构：记录按关键字排序，可折半查找，效率高，但插入/删除需要保持有序
- 优点：顺序存取效率高，适合批量处理；缺点：随机存取效率低，适合顺序访问的设备
- 定长记录的顺序文件可按记录号直接计算出地址：第 i 条记录地址 = 起始地址 + i × 记录长度
### 索引文件
- 为变长记录文件建立一张索引表，每个记录对应一个索引项（记录长度 + 记录地址）
- 索引表本身是定长记录的顺序文件，因此可按记录号直接定位索引项
- 优点：支持随机访问，检索速度快；缺点：索引表占用额外空间，增加了存储开销
### 索引顺序文件
- 将记录分为若干组，为每组的第一条记录建立索引项，形成索引表；组内顺序查找
- 检索时先查索引表找到组，再在组内顺序查找；平均查找次数约为 √N
- 两级索引顺序文件：为索引表再建立索引，检索效率进一步提高，需要 log₂N 次左右
- 优点：兼顾顺序文件和索引文件的优点，索引表小、开销小；缺点：组内仍需顺序查找
### 直接文件（散列文件）
- 根据记录的关键字通过散列函数直接计算出记录的物理地址
- 优点：存取速度快；缺点：可能出现冲突（不同关键字映射到同一地址），需要解决冲突
## 文件的物理结构
- 文件的物理结构：文件在磁盘上的存放方式，即文件分配方式
- 磁盘块（盘块）是外存分配的基本单位，大小通常为 1KB、2KB、4KB
- 文件在逻辑上分为若干块，物理上存放在若干盘块中
- ![[文件物理结构.svg]]
### 连续分配
- 文件占用磁盘上连续的盘块，目录项记录起始块号和文件长度（块数）
- 优点：支持顺序访问和随机访问（可直接计算出第 i 块的地址），访问速度快，磁头移动少
- 缺点：文件不易扩展；会产生外部碎片（磁盘碎片）；必须知道文件大小才能分配
- 适用：一次性写入、大小固定的文件（如 ISO 镜像、视频文件）
### 链接分配（隐式链接）
- 文件占用离散的盘块，每个盘块中存放指向下一个盘块的指针，最后一块的指针为 -1（或 NULL）
- 目录项记录起始块号和结束块号
- 优点：无外部碎片，文件可动态扩展，磁盘空间利用率高
- 缺点：只能顺序访问，不支持随机访问（要访问第 i 块必须从第一块开始读）；指针占用盘块空间；可靠性差（指针损坏则后面的数据全部丢失）
### 链接分配（显式链接）
- 把链接指针集中在内存的一张表（文件分配表 FAT，File Allocation Table）中，盘块本身只存数据
- FAT 的表项数 = 磁盘盘块数，表项内容为下一个盘块的块号，-1 表示文件结束，0 表示空闲
- 优点：支持随机访问（在 FAT 中沿链查找，不需访问磁盘）；无外部碎片
- 缺点：FAT 需要常驻内存，占用大量内存空间（磁盘大时 FAT 很大）
- 常考：FAT 的表项数等于磁盘盘块数，与文件个数无关；每个表项占几个字节由盘块号位数决定；FAT 需要常驻内存，磁盘越大占用越多
### 索引分配
- 为每个文件分配一个索引块，索引块中存放该文件所有盘块的块号；目录项记录索引块的块号
- 优点：支持随机访问，无外部碎片，文件可动态扩展
- 缺点：索引块占用额外空间；文件很大时索引块可能装不下
- 解决索引块装不下的方法：
	1. 链接方案：把多个索引块链接起来，最后一块的指针为 -1；查找后面的索引块需要顺序读取
	2. 多层索引：第一层索引块指向第二层索引块，第二层指向数据块；类似多级页表，访问数据需要多次读盘
	3. 混合索引（UNIX 采用）：索引结点中同时包含直接地址项和间接地址项
### UNIX 混合索引
- 索引结点（inode）中设置 13 个地址项：
	- 10 个直接地址项：直接指向数据块，可支持小文件
	- 1 个一次间接地址项：指向一个索引块，索引块中存放数据块号
	- 1 个二次间接地址项：指向索引块，其表项指向一次间接索引块
	- 1 个三次间接地址项：指向索引块，其表项指向二次间接索引块
- 设盘块大小 1KB、每个地址项 4B，则一个索引块可存放 256 个地址
- 最大文件大小 = (10 + 256 + 256² + 256³) × 1KB
- 优点：小文件访问快（直接地址），大文件也能支持；缺点：大文件访问需要多次读盘
- 常考：给定文件大小求需要访问几次磁盘、给定块号求在哪一级索引中

### 三种物理结构的对比
| 对比项 | 连续分配 | 链接分配（隐式） | 链接分配（显式 FAT） | 索引分配 |
| --- | --- | --- | --- | --- |
| 顺序访问 | 支持，快 | 支持 | 支持 | 支持 |
| 随机访问 | 支持 | 不支持 | 支持 | 支持 |
| 外部碎片 | 有 | 无 | 无 | 无 |
| 文件扩展 | 困难 | 容易 | 容易 | 容易 |
| 额外开销 | 无 | 指针占盘块空间 | FAT 占内存 | 索引块占磁盘空间 |
| 可靠性 | 好 | 差 | 较好 | 好 |
## 文件目录
### 文件控制块 FCB
- FCB：用于描述和控制文件的数据结构，与文件一一对应，是文件存在的标志
- FCB 包含三类信息：
	1. 基本信息：文件名、物理位置、文件逻辑结构、物理结构、文件大小
	2. 存取控制信息：文件存取权限（属主、同组用户、其他用户的读/写/执行权限）
	3. 使用信息：创建时间、最后修改时间、当前使用状态等
- 目录项：FCB 的有序集合构成文件目录，一个目录项就是一个 FCB；目录本身也是一种文件
- 目录管理的要求：实现按名存取、提高检索速度、允许文件重名、便于文件共享
### 单级目录结构
- 整个文件系统只有一张目录表，每个文件占一个目录项
- 优点：实现简单，能实现按名存取
- 缺点：不允许文件重名；文件多时查找慢；不便于文件共享；不便于对文件分类
### 两级目录结构
- 分为主文件目录（MFD）和用户文件目录（UFD）
- MFD 记录用户名及相应用户目录的存储位置；UFD 记录该用户的文件
- 优点：不同用户可以使用相同文件名；提高了检索速度；一定程度上实现了共享
- 缺点：缺乏灵活性，不能对文件分类；用户之间不能共享文件
### 树形目录结构
- 目录按树形层次组织，根目录在最上层，每个目录下可以有子目录和文件
- 路径名：从根目录出发的绝对路径、从当前目录出发的相对路径
- 当前目录（工作目录）：进程当前所在的目录，用相对路径可减少路径检索时间
- 优点：便于文件分类和组织，层次清晰；便于实现文件保护；查找效率较高
- 缺点：不便于实现文件共享（不同用户要访问同一文件时，需要在各自的目录中建立副本）
- 常考：绝对路径与相对路径的转换；树形目录中文件的完整路径
### 无环图目录结构
- 在树形目录的基础上，增加指向同一文件（或目录）的共享指针，形成有向无环图
- 共享文件只有一个副本，多个用户通过不同的路径访问它
- 用共享计数器 count 记录指向该文件的链接数；删除文件时 count 减 1，只有 count 为 0 时才真正删除
- 优点：实现文件共享，节省存储空间；缺点：结构复杂，需要维护共享计数
### 索引结点
- 将文件名与文件的描述信息分开：目录项只包含文件名和索引结点号（inode 号）
- 索引结点（inode）存放除文件名以外的全部 FCB 信息（文件类型、大小、物理地址、权限、时间等）
- 优点：目录项变小，一个盘块能存放更多目录项，减少目录检索时的磁盘 I/O 次数；便于文件共享（多个目录项指向同一 inode）
- 磁盘索引结点与内存索引结点：打开文件时把磁盘 inode 复制到内存 inode，并增加引用计数等运行时信息
### 硬链接与软链接
- 硬链接（基于索引结点的共享）：多个目录项指向同一个 inode，inode 的链接计数 count 增加
	- 删除其中一个目录项只是 count 减 1，文件数据仍然存在
	- 不能跨文件系统建立；只有文件能建立硬链接，目录不能（避免形成环）
	- 访问速度快，直接通过 inode 找到数据
- 软链接（符号链接）：创建一个新的链接文件（类型为 link），其内容是目标文件的路径名
	- 可以跨文件系统；可以给目录建立软链接；目标文件删除后链接仍然存在，但成为悬空链接（访问失败）
	- 访问时需要先读链接文件、解析路径，再访问目标文件，速度较慢
- 对比：硬链接共享 inode，软链接是独立的文件；硬链接的 count 是引用计数，软链接不增加目标文件的 count
### 文件保护
- 口令保护：文件设置口令，访问时核对口令；开销小，但口令存放在系统中，安全性差
- 加密保护：对文件加密，访问时用密钥解密；安全性好，但加密解密增加开销
- 访问控制：为每个文件设置访问控制列表（ACL），列出每个用户（或用户组）的访问权限
	- 访问控制矩阵：行是用户、列是文件，矩阵元素是权限；矩阵稀疏，存储浪费
	- 按列保存为访问控制列表 ACL：每个文件一张表，记录哪些用户有何权限
	- 按行保存为访问能力表：每个用户一张表，记录该用户能访问哪些文件及权限
- 常考：ACL 是"文件视角"，能力表是"用户视角"；两者可以互相转换
## 文件系统的层次结构
### 文件系统的层次
1. 用户接口：提供 open、read、write、close 等系统调用
2. 文件目录系统：管理目录，实现按名存取、路径解析
3. 存取控制模块：验证用户对文件的访问权限
4. 逻辑文件系统与文件信息缓冲区：把逻辑记录号转换为物理块号，管理文件缓冲区
5. 物理文件系统：管理磁盘空间的分配与回收，把逻辑块号转换为物理块号
6. 设备管理程序与设备驱动程序：与磁盘等设备交互，完成实际的 I/O
### 文件系统的布局
- 引导块：位于文件系统起始处，存放引导加载程序，用于启动操作系统
- 超级块：记录文件系统的整体信息（文件系统类型、大小、空闲块数量、inode 数量、空闲空间管理数据结构等）
- 空闲空间管理区：位示图、空闲链表、成组链接等的存放区域
- 索引结点区：存放所有 inode，每个文件一个 inode
- 根目录与数据区：存放目录文件和普通文件的数据
### 文件系统的挂载
- 挂载（mount）：把一个文件系统附加到当前目录树的某个目录（挂载点）上，使两个文件系统合并成一棵目录树
- 挂载后，通过挂载点访问的是被挂载文件系统的根目录；卸载（umount）后恢复原来的目录
- 同一文件系统可以挂载多次；挂载点必须是一个空目录
### 虚拟文件系统 VFS
- VFS：在文件系统之上提供统一的抽象接口，使上层系统调用可以透明地访问不同类型的文件系统
- 四种对象：
	1. 超级块对象（superblock）：表示一个已挂载的文件系统，记录其类型、大小、操作函数表
	2. 索引结点对象（inode）：表示一个文件，记录文件的元数据和操作函数表
	3. 目录项对象（dentry）：表示路径中的一个分量（目录项），用于加速路径解析
	4. 文件对象（file）：表示一个已打开的文件，记录进程的读写位置和操作函数表
- VFS 通过函数指针表（操作函数集）调用具体文件系统的实现，实现"同一接口、多种实现"
## 文件存储空间管理
### 空闲表法
- 为磁盘上的所有空闲区建立一张空闲表，每个空闲区对应一个表项（起始块号、空闲块数）
- 分配时按算法（首次适应、最佳适应等）查找空闲区；回收时合并相邻空闲区
- 适用于连续分配方式；分配和回收类似动态分区分配
### 空闲链表法
- 空闲盘块链：以盘块为单位，把所有空闲盘块链接成一条链；分配和回收都以盘块为单位，操作简单但效率低（每次分配可能需要多次读盘）
- 空闲盘区链：以盘区（连续空闲块）为单位链接；分配时按盘区大小查找，回收时合并相邻盘区；效率较高，实现复杂
### 位示图法
- 用若干字节（或字）的二进制位表示盘块的使用情况：0 表示空闲，1 表示已分配
- 位示图的每一位对应一个盘块，位示图的大小 = ⌈盘块数 / 8⌉ 字节
- 盘块号与（字号 i，位号 j）的换算（行、列均从 0 开始，每行 n 位）：
	- 盘块号 b = i × n + j
	- 字号 i = ⌊b / n⌋，位号 j = b mod n
- 分配：顺序扫描位示图，找到为 0 的位，计算盘块号并分配，将该位置 1
- 回收：由盘块号计算字号和位号，将该位置 0
- 优点：便于查找连续的空闲块；缺点：位示图需要常驻内存，大磁盘时占用空间较大
### 成组链接法
- UNIX 系统采用的方法，把空闲盘块分成若干组，每组通常 100 个空闲块
- 超级块中存放第一组的空闲块数和这些块的块号；每组的第一块（或最后一块）记录下一组的空闲块数和块号，形成链式结构
- 分配：从当前组（超级块中记录的那组）取空闲块；当前组只剩最后一块时，先把该块中记录的下一组信息读入超级块，再分配该块
- 回收：把回收的盘块放入当前组；当前组满 100 块时，把当前组的块号写入新回收的块中，并把该块作为新一组的"组长"登记到超级块
- 优点：既克服了空闲链表需要遍历的缺点，又不需要像位示图那样占用大量内存；适合大型文件系统
- 常考：成组链接法中超级块与各组之间的指针关系；分配/回收时超级块的变化

# 第五章 输入输出管理
## I/O 管理概述
### I/O 设备
- 按使用特性分类：
	1. 人机交互类外部设备：如键盘、鼠标、打印机，速度慢
	2. 存储设备：如磁盘、光盘、U 盘，速度快
	3. 网络通信设备：如网卡、调制解调器
- 按传输速率分类：低速设备、中速设备、高速设备
- 按信息交换的单位分类：
	1. 块设备：以数据块为单位传输，如磁盘；传输速率高，可寻址（可随机读写任意块）
	2. 字符设备：以字符为单位传输，如键盘、打印机；传输速率低，不可寻址，常采用中断方式
- 设备接口：设备与主机之间通过设备控制器（I/O 接口）连接
### I/O 控制器
- 作用：CPU 与设备之间的中介，接收 CPU 的命令、控制设备工作、向 CPU 报告状态
- 组成：
	1. CPU 与控制器之间的接口：数据寄存器、控制/状态寄存器
	2. I/O 逻辑：对 CPU 的命令进行译码，并向设备发出控制信号
	3. 控制器与设备之间的接口：一个控制器可连接多台设备
- 控制器中的寄存器：数据寄存器（暂存数据）、控制寄存器（存放 CPU 发来的命令）、状态寄存器（记录设备状态）
### I/O 端口
- I/O 端口：设备控制器中可被 CPU 直接访问的寄存器
- 编址方式：
	1. 独立编址（端口编址）：I/O 端口有独立的地址空间，与内存地址空间分开；CPU 需要专门的 I/O 指令（如 IN、OUT）访问端口
	2. 内存映射编址（统一编址）：把 I/O 端口映射到内存地址空间，用普通的访存指令即可访问；不需要专门的 I/O 指令，但占用了内存地址空间
- 常考：独立编址需要专门的 I/O 指令；内存映射编址可以用访存指令访问 I/O 端口
## I/O 控制方式
### 程序直接控制方式（轮询）
- CPU 不断循环检测设备状态寄存器，直到设备就绪后再进行数据传输
- 数据传送由 CPU 完成：CPU 从设备读入数据寄存器，再写入内存
- 优点：实现简单，不需要额外的硬件支持
- 缺点：CPU 大量时间用于轮询，CPU 与设备串行工作，CPU 利用率极低
### 中断驱动方式
- CPU 发出 I/O 命令后转去执行其他程序；设备完成一个字节（或一个字）的传输后向 CPU 发出中断，CPU 响应中断完成数据传送
- 优点：CPU 与设备并行工作，CPU 利用率提高
- 缺点：每传输一个字节（字）就要中断一次，中断频繁，CPU 开销大
- 常考：中断驱动方式中数据传送仍由 CPU 完成，设备与内存之间没有直接通路
### DMA 方式
- DMA（直接存储器存取）：由 DMA 控制器控制数据块在内存与设备之间直接传送，不需要 CPU 干预
- 工作过程：
	1. CPU 向 DMA 控制器发出命令，设置内存起始地址、传送长度、传送方向
	2. DMA 控制器向设备发出命令，控制数据在设备与内存之间直接传送
	3. 整个数据块传送完毕后，DMA 控制器向 CPU 发出中断，CPU 做后处理
- 数据传送的基本单位是数据块，CPU 只在传送开始前和结束后干预
- 优点：CPU 与设备并行工作，CPU 开销小，适合高速块设备
- 缺点：DMA 控制器与 CPU 可能同时访问内存，产生冲突（需要总线仲裁）
- DMA 与中断的区别：中断方式下数据传送由 CPU 完成；DMA 方式下数据传送由 DMA 控制器完成，CPU 只在开始和结束时干预
### 通道控制方式
- 通道：一种专门负责 I/O 控制的处理器（I/O 处理机），可以执行通道程序，控制多台设备
- CPU 向通道发出 I/O 命令，通道执行通道程序，控制设备完成一组数据块的传送；完成后通道向 CPU 发中断
- 优点：进一步减少 CPU 的干预，CPU、通道、设备可并行工作，适合大型机
- 缺点：需要专门的通道硬件，成本高
- 通道与 DMA 的区别：DMA 一次只能控制一台设备的一个数据块传送；通道可以控制多台设备、执行多条通道命令
### 四种 I/O 控制方式的对比
| 对比项 | 程序直接控制 | 中断驱动 | DMA | 通道 |
| --- | --- | --- | --- | --- |
| 数据传送单位 | 字节/字 | 字节/字 | 数据块 | 一组数据块 |
| 数据传送者 | CPU | CPU | DMA 控制器 | 通道 |
| CPU 干预频率 | 全程轮询 | 每个字节中断一次 | 每个数据块一次 | 一组数据块一次 |
| CPU 与设备并行 | 不能 | 能 | 能 | 能（CPU、通道、设备三级并行） |
| 硬件开销 | 最小 | 较小 | 较大 | 最大 |
## I/O 软件层次结构
- 从用户到硬件，I/O 软件分为四层：
	1. 用户层 I/O 软件：实现与用户交互的接口，如库函数（printf、scanf），将用户请求转换为系统调用
	2. 设备独立性软件（系统调用处理层）：实现与设备无关的功能
		- 缓冲管理、设备分配与回收、设备独立性（逻辑设备名到物理设备名的映射）、差错处理、设备保护
		- 向上提供统一的系统调用接口（read、write、open、close 等）
	3. 设备驱动程序：与具体硬件直接相关，把抽象的 I/O 请求转换为设备能识别的命令和参数，启动设备工作
		- 每类设备对应一个驱动程序；负责设置设备寄存器、检查设备状态
	4. 中断处理程序：当 I/O 完成或出错时，负责处理中断，唤醒等待的进程
- 硬件层：具体的 I/O 设备与控制器
- 常考：设备独立性软件的"设备独立性"是指用户使用逻辑设备名，由系统映射到物理设备；设备驱动程序是唯一与硬件直接相关的一层
## 设备独立性软件
### 逻辑设备名与物理设备名
- 逻辑设备名：用户程序使用的设备名（如打印机），与具体物理设备无关
- 物理设备名：系统内部标识具体设备的编号
- 逻辑设备表（LUT）：记录逻辑设备名到物理设备名及驱动程序入口地址的映射；每个用户一张或整个系统一张
- 优点：用户程序与具体设备无关，设备更换时程序不需修改；便于实现设备的共享与分配
### 设备的分配与回收
- 设备分配的数据结构：
	1. 设备控制表（DCT）：每个设备一张，记录设备类型、设备标识、状态（忙/闲）、指向 COCT 的指针、等待队列指针
	2. 控制器控制表（COCT）：每个控制器一张，记录控制器状态、指向 CHCT 的指针、等待队列
	3. 通道控制表（CHCT）：每个通道一张，记录通道状态、指向 COCT 的指针、等待队列
	4. 系统设备表（SDT）：整个系统一张，记录系统中全部设备的情况，每台设备一个表项，指向该设备的 DCT
- 分配过程：从 SDT 找到设备 → 查 DCT 判断是否可用 → 查 COCT 找到控制器 → 查 CHCT 找到通道 → 三者都可用则分配，否则排入等待队列
### 静态分配与动态分配
- 静态分配：作业开始运行前一次性分配所需的全部设备，运行结束后释放
	- 优点：不会发生死锁；缺点：设备利用率低（设备可能长时间闲置）
- 动态分配：作业运行过程中根据需要申请设备，用完立即释放
	- 优点：设备利用率高；缺点：可能出现死锁（多个进程互相等待设备）
- 设备分配算法：先来先服务、优先级高者优先
### SPOOLing 技术（假脱机技术）
- SPOOLing（Simultaneous Peripheral Operations On-Line）：用软件模拟脱机输入/输出，把独占设备改造为共享设备
- 组成：
	1. 输入井和输出井：在磁盘上开辟的存储区域，模拟脱机输入/输出时的磁带
	2. 输入缓冲区和输出缓冲区：在内存中开辟的区域，缓和 CPU 与磁盘速度不匹配的矛盾
	3. 输入进程和输出进程：模拟脱机输入/输出时的外围控制机
- 以共享打印机为例：用户进程申请打印时，SPOOLing 系统在输出井中为其申请一块缓冲区，把要打印的数据送入其中，并为其挂一个打印请求表；打印进程按队列顺序实际打印
- 优点：提高了 I/O 速度；把独占设备改造为共享设备（如共享打印机）；实现了虚拟设备功能
- 常考：SPOOLing 技术需要磁盘（输出井）和多道程序技术支持；打印机是典型的独占设备，经 SPOOLing 改造后可共享

## 缓冲区管理
### 缓冲区的概念
- 缓冲区：一个存储区域，用于缓和 CPU 与 I/O 设备速度不匹配的矛盾，减少中断频率，提高 CPU 与设备的并行性
- 缓冲的实现：硬件缓冲（专用缓冲寄存器，成本高）、软件缓冲（内存中开辟的区域，常用）
- 单缓冲、双缓冲、循环缓冲、缓冲池
### 单缓冲
- 在设备和处理机之间设置一个缓冲区
- 输入时：设备把数据送入缓冲区（时间 T），CPU 从缓冲区取走数据（时间 M），二者不能完全并行；处理数据时间 C
- 每块数据的处理时间 = max(C, T) + M
- 处理 n 块数据的总时间 = n × [max(C, T) + M]
### 双缓冲
- 设置两个缓冲区，设备输入第一个缓冲区的同时，CPU 可处理第二个缓冲区中的数据
- 每块数据的处理时间 = max(C + M, T)
- 处理 n 块数据的总时间 = n × max(C + M, T)
- 双缓冲进一步提高了并行性；当 T > C + M 时，设备是瓶颈；当 T < C + M 时，CPU 是瓶颈
- ![[缓冲时序.svg]]
### 循环缓冲
- 多个大小相等的缓冲区组成环形队列，设置 in 和 out 指针
- 输入进程不断把数据写入缓冲区，输出进程不断取出数据；in 追上 out 表示满，out 追上 in 表示空
- 适合输入/输出速度基本匹配的情况
### 缓冲池
- 由多个大小相同的缓冲区组成，供多个进程共享；缓冲池中的缓冲区按用途分为：
	1. 空白缓冲队列（emq）：空闲的缓冲区
	2. 输入队列（inq）：装满输入数据的缓冲区
	3. 输出队列（outq）：装满输出数据的缓冲区
- 四种工作缓冲区：收容输入、提取输入、收容输出、提取输出
- 工作过程：输入进程从 emq 取空缓冲区收容输入数据，送入 inq；计算进程从 inq 取缓冲区提取数据，用完后放回 emq；输出类似
- 优点：缓冲区可被多个进程共享，提高了缓冲区的利用率
## 磁盘管理
### 磁盘的结构
- 磁盘由若干盘片组成，每个盘片有两个盘面，每个盘面有一个磁头
- 盘面划分为若干同心圆磁道，每条磁道划分为若干扇区（盘块）
- 柱面：所有盘面上相同编号的磁道组成一个柱面
- 磁盘地址：柱面号（磁道号）+ 盘面号（磁头号）+ 扇区号
- 磁盘容量 = 磁头数 × 磁道数 × 每道扇区数 × 扇区大小
- 常考：访问磁盘时先移动磁头到指定柱面（寻道），再旋转到指定扇区（旋转延迟），最后读写
### 磁盘访问时间
- 寻道时间 Ts：磁头移动到指定磁道所需的时间
	- $T_s = m \times n + s$，其中 n 为跨越的磁道数，m 为每跨越一个磁道所需时间，s 为启动磁臂的时间
- 旋转延迟时间 Tr：指定扇区旋转到磁头下方所需的时间
	- 平均旋转延迟 = 半圈时间 = $\frac{1}{2r}$，r 为磁盘转速（转/秒）
	- 若告诉转速为每分钟 R 转，则 r = R / 60
- 传输时间 Tt：读写数据所需的时间
	- $T_t = \frac{b}{rN}$，b 为读写的字节数，N 为一条磁道上的字节数
- 总访问时间 T = Ts + Tr + Tt
### 磁盘调度算法
- 先来先服务（FCFS）：按请求到达的顺序服务
	- 优点：公平、简单；缺点：平均寻道时间长，性能差
- 最短寻道时间优先（SSTF）：每次选择距当前磁头位置最近的请求
	- 优点：平均寻道时间短；缺点：可能产生饥饿（远处的请求长期得不到服务）
- 扫描算法（SCAN，电梯算法）：磁头沿一个方向移动，沿途服务所有请求，到达磁盘端点（或该方向最远的请求）后反向
	- 优点：避免了饥饿；缺点：对两端磁道的请求不公平（中间磁道被服务两次，两端磁道等待时间长）
- 循环扫描算法（C-SCAN）：磁头只在一个方向上服务请求，到达端点后快速返回起始端（返回途中不服务），再重新开始
	- 优点：对各磁道的请求更公平；缺点：返回开销大
- LOOK 算法：SCAN 的改进，磁头移动到该方向上最远的请求就反向，不必到达磁盘端点
- C-LOOK 算法：C-SCAN 的改进，只移动到最远的请求就返回
- 常考：题中给出"磁头当前位于某磁道、向磁道增大方向移动"，需按方向计算移动量；SCAN/C-SCAN 要移动到端点，LOOK/C-LOOK 移动到最远请求
- ![[磁盘调度轨迹.svg]]
### 磁盘调度例题
- 磁道请求序列：55, 58, 39, 18, 90, 160, 150, 38, 184；磁头当前位于 100 号磁道，向磁道号增大的方向移动
- FCFS：移动总量 = 45 + 3 + 19 + 21 + 72 + 70 + 10 + 112 + 146 = 498
- SSTF：100→90→58→55→39→38→18→150→160→184，移动总量 = 10 + 32 + 3 + 16 + 1 + 20 + 132 + 10 + 24 = 248
- LOOK（先向增大方向）：100→150→160→184→90→58→55→39→38→18，移动总量 = 50 + 10 + 24 + 94 + 32 + 3 + 16 + 1 + 20 = 250
- C-LOOK：100→150→160→184 后返回最小于请求 18，再 18→38→39→55→58→90，移动总量 = 84 + 166 + 72 = 322
- 结论：SSTF 平均寻道时间最短但可能饥饿；SCAN 类算法避免了饥饿，但移动量不一定最小
### 磁盘格式化与坏块管理
- 磁盘格式化：
	1. 低级格式化（物理格式化）：划分扇区，为每个扇区建立头标、数据区和校验码；通常在出厂时完成
	2. 分区：把磁盘划分为若干分区（如 C 盘、D 盘）
	3. 逻辑格式化（高级格式化）：在分区上建立文件系统，初始化目录、空闲空间管理数据结构、根目录等
- 引导块：磁盘的第一个扇区（主引导记录 MBR）存放引导程序，用于启动操作系统；包含分区表和引导代码
- 坏块管理：
	- 简单磁盘：在 FAT 或空闲空间管理中标记坏块，使其不被分配
	- 复杂磁盘：由磁盘控制器维护坏块链表，并用备用扇区替换坏块（对操作系统透明）
## 固态硬盘 SSD
- 基于闪存（Flash Memory）的存储设备，没有机械部件，由闪存翻译层（FTL）和闪存芯片组成
- 闪存翻译层（FTL）：把逻辑块地址映射为物理页地址，并负责磨损均衡
- 读写特性：
	- 以页为单位读写，以块为单位擦除（一页通常 4KB，一块包含若干页）
	- 写入前必须先擦除所在块；擦除次数有限（寿命限制）
	- 读速度快，写速度慢（尤其是随机写），且写入会放大
- 磨损均衡：让各闪存块的擦除次数尽量均匀，延长寿命
	- 动态磨损均衡：写入时优先选择擦除次数少的块
	- 静态磨损均衡：定期把长期不动的数据迁移到擦除次数少的块，即使没有写入操作
- 与磁盘对比：SSD 随机访问速度快、无寻道和旋转延迟、抗震动、功耗低；但价格高、寿命有限、写入放大
- 常考：SSD 的随机读写性能优于磁盘；磨损均衡由 FTL 实现；SSD 也存在"写放大"问题
