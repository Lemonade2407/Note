## 数据库系统的三级模式结构
### 模式的概念
- 模式也称逻辑模式，是数据库中全体数据的逻辑结构和特征的描述，具体值称为实例
- 模式反映的是数据的结构及其联系，实例反映的是数据库某一时刻的状态
### 三级模式结构
- 模式、外模式、内模式
#### 模式
- 模式是所有用户的公共数据视图，一个数据库对应一个模式
#### 外模式
- 也称子模式/用户模式，是数据库用户能够看见和使用的局部数据的逻辑结构和特征的描述，是数据库用户的数据视图，一个数据库可以有多个外模式
#### 内模式
- 也称物理模式/存储模式，是对数据物理结构和存储方式的描述，是数据在数据库内部的组织方式，一个数据库只有一个内模式
#### 三级模式与两级映像
![[三级模式与两级映像.svg]]
- 外模式/模式映像：定义外模式与模式之间的对应关系，当模式改变时只要调整该映像，外模式可以不变，从而保证数据的逻辑独立性
- 模式/内模式映像：定义模式与内模式之间的对应关系，当存储结构改变时只要调整该映像，模式可以不变，从而保证数据的物理独立性
- 一个数据库只有一个模式、一个内模式，但可以有多个外模式；外模式是保证数据库安全性的有力措施之一
- 常考判断：应用程序依赖外模式，所以“模式变、外模式不变”是逻辑独立性，“内模式变、模式不变”是物理独立性

# 关系模型
## 数据结构及形式化定义
### 关系
- 域($D_1,D_2,...,D_n$)：一组具有相同数据类型的值的集合
	- 基数($M=\Pi^n_{i=1}m_i$)：域的不同取值个数
- 笛卡尔积($D_1\times D_2\times\dots\times D_n$)：域上的集合运算
	- 元组($d_1,d_2,...,d_n$)：笛卡尔积的每个元素
	- 分量($d_i$)：元组中的每一个值
- 关系($R(D_1,D_2,...,D_n)$)：笛卡尔积的有限子集
	- 基本关系
		- 列是同质的：分量来自同一个域、有相同数据类型
		- 不同列可出自同一个域
		- 列无序
		- 码不可重复
		- 行无序
		- 分量不可再分
	- 查询结果
	- 视图
### 关系模式
- 关系模式（$R(U,D,DOM,F)$)：关系的描述
	- R为关系名，U为属性名集合，D为域，DOM为属性向域的映像（说明分别出自哪个域）集合，F为属性间数据依赖关系的集合
	- DOM直接说明为属性的类型、长度
- 候选码：可以唯一标识一个元组的属性（组），诸属性被称为主属性，其余为非主（码）属性
- 主码：从候选码中选定一个，在名称下加下划线表示
- 全码：所有属性都是候选码
### 关系数据库
- 关系数据库系统：支持关系模型的数据库系统
- 关系数据库模式：对关系数据库的描述，所有关系模式的集合
- 关系数据库：关系模式对应的关系的集合

## 关系代数
- 用关系运算表达查询
### 传统的集合运算
- 并、差、交、笛卡尔积
### 专门的关系运算
- 选择：R中满足条件的元组，记作$\sigma_F(R)$，F为条件式
- 投影：R中若干属性组成新关系，记作$\Pi_A(R)$，A为R的属性列
- 连接：两个关系的笛卡尔积中选取属性满足条件$\theta$的元组，记作$R\bowtie_{A\theta B} S$
	- 等值连接：A=B
	- 自然连接：属性同名的等值连接
		- 外连接：保留含空值元组
			- 左外连接：保留左侧所有元组（左侧无空值）
			- 右外连接：保留右侧所有元组（右侧无空值）
- 除：R除S的结果包含在R但不在S的属性及值，记为$R\div S$
### 除运算的例题
- 设有关系 $R(A,B)$ 与 $S(B)$：$R=\{(a_1,b_1),(a_2,b_1),(a_1,b_2),(a_1,b_3)\}$，$S=\{(b_1),(b_2)\}$，则 $R\div S=\{(a_1)\}$
- 求法：先找出 S 在 R 中对应属性上的全部值，再挑出这样的 x，它在 R 中对应的 y 集合包含 S 的全部值
- 典型用途：“选修了全部课程的学生”“供应了所有零件的供应商”
### 外连接补充
- 左外连接 $R⟕S$：保留 R 的全部元组，S 中无匹配的属性补空值
- 右外连接 $R⟖S$：保留 S 的全部元组
- 外连接不是基本运算，可由并、差、笛卡尔积、选择、投影组合得到
## 关系演算
- 关系演算：用谓词逻辑表达查询，只说明“要什么”，不说明“怎么做”
- 元组关系演算：$\{t \mid P(t)\}$，t 为元组变量，P 为谓词公式
	- 原子公式有三类：$R(t)$（t 是关系 R 的元组）、$t[i]\ \theta\ c$（元组分量与常量比较）、$t[i]\ \theta\ u[j]$（两个元组分量比较）
	- 公式可用 $\neg$、$\wedge$、$\vee$、$\Rightarrow$ 连接，可用 $\exists t$、$\forall t$ 量化
	- 典型语言：ALPHA、QUEL
	- 例：查询选修了 1 号课程的学生姓名，可写为 $\{t^{(2)} \mid (\exists u)(SC(u) \wedge u[1]=t[1] \wedge u[2]='1')\}$
- 域关系演算：$\{(x_1,x_2,\dots,x_n) \mid P(x_1,\dots,x_n)\}$，变量取值为域中的值
	- 典型语言：QBE（Query By Example）
- 安全约束：只允许表达式产生有限的结果，否则运算无意义
- 关系完备性：一个语言如果能表达关系代数中的全部运算，则称它是关系完备的。关系代数、元组演算、域演算三者等价；SQL 是关系完备的语言
- 三种语言的关系：关系代数（过程化）↔ 关系演算（非过程化），SQL 兼具二者特点

## 数据查询
- 一般格式：
```
SELECT[ALL|DISTINCT]<目标列表达式>[别名][,<目标列表达式>[别名]]...
FROM <表名/视图名>[别名][,<表名/视图名>[别名]]...
[WHERE <条件表达式>]
[GROUP BY <列名1>[HAVING <条件>]]
[ORDER BY <列名2>[ASC|DESC]]
[LIMIT <行数1>[OFFSET<行数2>]]
```
### 单表查询要点
- 查询指定列：`SELECT Sno, Sname FROM Student;`；查询全部列：`SELECT * FROM Student;`
- 查询经过计算的列：`SELECT Sname, 2026-Sage AS 出生年份 FROM Student;`（AS 可省略，别名便于阅读）
- 消除重复行：`SELECT DISTINCT Sdept FROM Student;`（作用于整个结果元组）
- 条件查询的谓词：比较运算符、`BETWEEN ... AND ...`、`IN`、`LIKE`、`IS NULL`、`AND/OR/NOT`
	- 字符匹配：`%` 代表任意长度字符串，`_` 代表任意单个字符；含 `%`、`_` 时用 ESCAPE 指定转义符
	- 空值判断只能用 `IS NULL` / `IS NOT NULL`，不能用 `= NULL`
- 排序：`ORDER BY 列名 [ASC|DESC]`，可多列排序，空值默认排在最前（ASC）
- 聚集函数：`COUNT`、`SUM`、`AVG`、`MAX`、`MIN`，除 `COUNT(*)` 外都跳过空值
- 分组：`GROUP BY 列名 [HAVING 条件]`；`WHERE` 作用于分组前（不能用聚集函数），`HAVING` 作用于分组后
- 例：查询平均成绩大于 90 的课程号
```sql
SELECT Cno, AVG(Grade) FROM SC GROUP BY Cno HAVING AVG(Grade) > 90;
```
### 连接查询要点
- 等值连接与自然连接：`SELECT Student.Sno, Sname, Cno, Grade FROM Student, SC WHERE Student.Sno = SC.Sno;`
- 自身连接：必须给表起两个别名，如“查询与刘晨同系的学生”
- 外连接：`FROM Student LEFT OUTER JOIN SC ON Student.Sno = SC.Sno`，保留左表全部元组，右表无匹配补空值
- 复合条件连接：`WHERE` 中可有多个连接条件与选择条件；多表连接时注意消除同名属性的歧义（用表名前缀）
### 嵌套查询要点
- 不相关子查询：子查询的执行不依赖外层查询的当前元组，先算子查询再代回
- 相关子查询：子查询中引用了外层查询的列，外层每取一个元组就执行一次
- `IN` 谓词：`SELECT Sname FROM Student WHERE Sno IN (SELECT Sno FROM SC WHERE Cno = '1');`
- 比较运算符 + `ANY`/`ALL`：`> ALL (SELECT Grade FROM SC WHERE Cno='1')` 表示大于 1 号课的全部成绩
- `EXISTS` 谓词：只判断子查询是否为空，`NOT EXISTS` 常用于“全部”语义，如“选修了全部课程的学生”
- 例：查询没有选修 1 号课程的学生姓名
```sql
SELECT Sname FROM Student
WHERE NOT EXISTS (SELECT * FROM SC WHERE SC.Sno = Student.Sno AND Cno = '1');
```
### 集合查询与派生表
- 并：`UNION`（自动去重）；交：`INTERSECT`；差：`EXCEPT`（MySQL 8.0 起才支持交与差）
- 参加集合运算的各查询结果列数必须相同、对应列的数据类型必须相容
- 派生表：把子查询放在 `FROM` 中当作临时表，必须起别名
```sql
SELECT Sdept, AVG(Sage) FROM (SELECT * FROM Student WHERE Ssex = '男') AS Male GROUP BY Sdept;
```
## 数据更新
### 插入数据
- 插入单个元组：`INSERT INTO Student(Sno, Sname, Ssex, Sdept, Sage) VALUES ('201215128', '陈冬', '男', 'IS', 18);`
- 省略列名时须按表的列顺序给出全部列值：`INSERT INTO Student VALUES ('201215128', '陈冬', '男', 18, 'IS');`
- 插入子查询结果（可一次插入多行，常用于生成汇总表）：
```sql
INSERT INTO Dept_age(Sdept, Avg_age)
SELECT Sdept, AVG(Sage) FROM Student GROUP BY Sdept;
```
- DBMS 会自动检查实体完整性与参照完整性，违约则拒绝插入
### 修改数据
- 语句：`UPDATE 表名 SET 列名 = 表达式 [, 列名 = 表达式 ...] [WHERE 条件];`
- 例：将计算机系全体学生年龄加 1：`UPDATE Student SET Sage = Sage + 1 WHERE Sdept = 'CS';`
- 例：把 1 号课程成绩提高 5%（带子查询）：`UPDATE SC SET Grade = Grade * 1.05 WHERE Cno = '1';`
- 不带 `WHERE` 表示修改全表所有元组，实际使用前务必先用 `SELECT` 验证条件
- 修改主码值可能违反参照完整性，需按预先定义的违约处理（拒绝/级联/置空）执行
### 删除数据
- 语句：`DELETE FROM 表名 [WHERE 条件];`
- 例：删除学号为 201215128 的记录：`DELETE FROM Student WHERE Sno = '201215128';`
- 例：删除所有计算机系学生的选课记录（相关子查询）：
```sql
DELETE FROM SC WHERE Sno IN (SELECT Sno FROM Student WHERE Sdept = 'CS');
```
- 删除是“按行删除”，`DELETE FROM 表名` 只删数据、保留表结构；`DROP TABLE` 连表结构一起删除
## 空值的处理
- 判断空值：IS NULL或IS NOT NULL
- 空值与另一值比较结果为UNKNOWN
## 视图
- 由表导出的虚表（不存储数据）
### 定义视图
- 创建
```
CREATE VIEW <视图名> [(<列名>[,<列名>]...)]
AS <子查询>
[WITH CHECK OPTION]
```
- 删除：`DROP VIEW <视图名> [CASCADE]`
### 查询视图
- 视图消解：把视图定义中的子查询和用户的查询结合，转换成等价的基本表查询
### 更新视图
- 通过视图来插入、删除、修改数据（通过视图消解转换为对基本表的更新）
### 视图的作用
- 保护机密数据
- 对重构数据库提供了一定逻辑独立性
- 简化用户操作
- 多角度看待同一数据

# 关系数据理论
## 问题的提出
- 如何构造合适的数据库模式；判断设计优良的标准
- 第一范式（1NF）：每个分量是不可分的数据项
- 数据依赖：一个关系属性和属性之间的约束关系。通过值的相等体现相关联系。
	- 函数依赖（FD）
	- 多值依赖（MVD）
## 规范化
### 函数依赖
- 如果两个元组的X属性相对，那Y属性也相等。称为X函数确定Y或Y函数依赖于X。记作$X\rightarrow Y$
- $X\rightarrow Y$，$Y\subsetneq X$，则称$X\rightarrow Y$为非平凡依赖
- $X\rightarrow Y$，X称为决定因素
- $X\rightarrow Y$，$Y\rightarrow X$，记作$X\leftarrow\rightarrow Y$
- 若Y函数不依赖于X，则记作$X\nrightarrow Y$
- 完全函数依赖：$X\rightarrow Y$且X的任意真子集X'都有$X'\nrightarrow Y$。记作$X\rightarrow^FY$
- 部分函数依赖：Y函数依赖于X但不完全依赖。记作$X\rightarrow^P Y$
- 传递函数依赖：$Y\subsetneq X$，$Z\subsetneq Y$，$X\rightarrow Y$，$Y\nrightarrow X$，$Y\rightarrow Z$，则称为Z对X传递函数依赖。记为$X\rightarrow^T Z$
### 码
- 若$K\rightarrow^FU$，则K为R的候选码；若$K\rightarrow^PU$，则K为超码
### 求候选码的属性分类法
- 把 U 中属性按在函数依赖中的出现位置分为四类：
	- L 类：只出现在依赖左边
	- R 类：只出现在依赖右边
	- LR 类：左右都出现
	- N 类：左右都不出现
- 结论：L 类与 N 类属性必定属于**每一个**候选码；R 类属性不属于任何候选码；LR 类属性可能属于候选码
- 步骤：先取 L∪N 求闭包，若 $X^+=U$ 则 X 就是唯一候选码；否则依次把 LR 类属性并进来再求闭包，使闭包等于 U 的最小属性组即为候选码
- 属性闭包求法：从 $X$ 出发，反复扫描 F，若某依赖 $A\to B$ 的 A 已包含在当前集合中，则把 B 并入，直到集合不再变化
- 例：$R(A,B,C,D)$，$F=\{A\to B,\ B\to C,\ AC\to D\}$。A 为 L 类，$A^+=\{A,B,C,D\}=U$，故候选码为 A；又 $AD\to$… 可验证只有 A 唯一
### 范式
- 满足要求的程度由低到高，第一范式->第四范式
- $4NF\subset BCNF\subset 3NF\subset 2NF\subset 1NF$
- 规范化：低级范式通过模式分解转换为n个高级范式
### 2NF
- 定义：若 $R\in 1NF$，且每一个非主属性都**完全函数依赖**于任何一个候选码，则 $R\in 2NF$
- 直观理解：消除了非主属性对候选码的**部分函数依赖**
- 判定：若候选码是单属性，则它一定是 2NF；若存在“候选码的真子集决定非主属性”，则只是 1NF
- 例：$SC(Sno, Cno, Grade)$ 候选码为 $(Sno,Cno)$，$Grade$ 完全依赖于它，所以 $SC\in 2NF$；而 $S-L-C(Sno,Sdept,Sloc,Cno,Grade)$ 中 $Sno\to Sdept$，$Sdept$ 部分依赖于码，故不属于 2NF
- 分解方法：把部分依赖的属性组单独成表，如把 $S-L-C$ 分解为 $SC(Sno,Cno,Grade)$ 与 $S-L(Sno,Sdept,Sloc)$
### 3NF
- 定义：若 $R\in 2NF$，且每个非主属性既不部分依赖也不**传递依赖**于候选码，则 $R\in 3NF$
- 直观理解：消除了非主属性对候选码的传递函数依赖
- 例：$S-L(Sno,Sdept,Sloc)$ 中 $Sno\to Sdept$、$Sdept\to Sloc$（且 $Sdept\nrightarrow Sno$），$Sloc$ 传递依赖于 $Sno$，故不是 3NF
- 分解方法：把传递依赖的“中间属性 + 被决定属性”单独成表，如 $S-D(Sno,Sdept)$ 与 $D-L(Sdept,Sloc)$
### BCNF
- 定义：若 $R\in 1NF$，且每个**决定因素都包含码**（即任何非平凡函数依赖 $X\to Y$ 的 X 都是超码），则 $R\in BCNF$
- 与 3NF 的区别：3NF 只约束非主属性，BCNF 约束所有属性（含主属性），条件更严
- 例：$STJ(S,T,J)$ 中 $S$ 为学生、$T$ 为教师、$J$ 为课程，语义为“每位教师只教一门课，每门课有若干教师，某学生选定某门课就固定了教师”，函数依赖为 $(S,J)\to T$、$(S,T)\to J$、$T\to J$，$T$ 是决定因素但不是码，故 $STJ\in 3NF$ 但不属于 BCNF
- 结论关系：$BCNF \subset 3NF \subset 2NF \subset 1NF$；规范化程度越高，连接操作越多、查询效率可能越低，实际设计常做到 3NF
### 范式判定的快速步骤
1. 求所有候选码（用属性闭包法），确定主属性与非主属性
2. 写出全部函数依赖，检查有无非主属性对码的部分依赖 → 有则只到 1NF
3. 检查有无非主属性对码的传递依赖 → 有则只到 2NF
4. 检查每个决定因素是否都包含码 → 都包含则到 BCNF，否则 3NF
5. 检查是否所有非平凡多值依赖的左部都包含码 → 是则到 4NF

## 数据依赖的公理系统
- 逻辑蕴含：若R<U,F>，中任意关系r均成立$X\rightarrow Y$，则称F逻辑蕴含$X\rightarrow Y$
- Armstrong公理系统（有效的、完备的）
	- 自反律：若$Y\subseteq X\subseteq U$，则F逻辑蕴含$X\rightarrow Y$
	- 增广律：F逻辑蕴含$X\rightarrow Y$，$Z\subseteq U$，则$XZ\rightarrow YZ$为F所蕴含
	- 传递律：F逻辑蕴含$X\rightarrow Y$，F逻辑蕴含$Y\rightarrow Z$，则F逻辑蕴含$X\rightarrow Z$
	- 合并规则：由$X\rightarrow Y,X\rightarrow Z$，有$X\rightarrow YZ$
	- 伪传递规则：由$X\rightarrow Y,WY\rightarrow Z$，有$XW\rightarrow Z$
	- 分解规则：由$X\rightarrow Y,Z\subseteq Y$，有$X\rightarrow Z$
	- $X\rightarrow A_1A_2...A_k$成立的充要条件是$X\rightarrow A_i$成立
	- 闭包：F所逻辑蕴含的全体称为F的闭包，记为$F^+$
### 函数依赖集的等价与最小依赖集
- 等价：若 $F^+=G^+$，则称 F 与 G 等价（互相覆盖）
- 最小依赖集（极小覆盖）$F_m$ 的三个条件：
	- F 中任一函数依赖的右边都是单属性
	- F 中不存在冗余的函数依赖（去掉任一依赖后闭包改变）
	- F 中任一函数依赖的左边没有冗余属性（去掉左边某属性后闭包改变）
- 求法：① 用分解规则把右边全部拆成单属性；② 逐个尝试去掉某依赖，若闭包不变则删除；③ 逐个尝试去掉左边某属性，若闭包不变则删除
- 最小依赖集一般不唯一，但所有最小依赖集包含的依赖个数相同
### 无损连接与保持函数依赖
- 无损连接分解：关系 R 分解为 $R_1,R_2$ 后，自然连接 $R_1\bowtie R_2$ 的结果与 R 完全相同（不丢失、不多出元组）
- 判定定理：R 分解为 $R_1,R_2$ 是无损连接的充要条件是 $R_1\cap R_2\to R_1-R_2$ 或 $R_1\cap R_2\to R_2-R_1$ 成立
- 保持函数依赖：分解后各子关系的函数依赖之并，能够逻辑蕴含原关系的全部函数依赖
- 关系：一个分解可能无损连接但不保持函数依赖，也可能保持依赖但不是无损连接；3NF 分解可以同时做到无损连接与保持函数依赖，BCNF 分解只能保证无损连接（不一定保持依赖）
- 常考结论：规范化通过分解实现，分解时必须用“无损连接 + 保持函数依赖”两条标准衡量优劣

## 逻辑结构设计
### E-R图向关系模型的转换
- 原则：一个实体型转换为一个关系模式
	- 1：1联系：可以转换为一个独立的关系模式，也可以与任意一端对应的关系模式合并
	- 1：n联系：可以转换为一个独立的关系模式，也可以与n端对应的关系模式合并
	- m：n联系：转换为一个关系模式
	- 三个及以上：转换为一个关系模式
	- 具有相同码的关系模式可以合并
### 逻辑结构设计的三个步骤
1. 将概念结构（E-R 图）转换为关系模型（一组关系模式）
2. 将转换得到的关系模型向特定 DBMS 支持的数据模型转换（类型、长度、约束、默认值）
3. 对数据模型进行优化：确定数据依赖、消除冗余联系、确定主键与外键、必要时做模式分解
- 优化的三条准则：① 分析函数依赖，消除冗余的联系；② 确定各关系模式的范式级别，必要时分解；③ 分析数据依赖，确定主键与外键
- 用户子模式（外模式）设计：为不同用户定义不同的视图，简化使用并保证安全性
## 物理结构设计
- 为给定的逻辑数据模型选取一个最适合应用要求的物理结构的过程
1. 确定数据库的物理结构
2. 对物理结构进行评价
- 确定物理结构的内容：
	- 存储结构：确定数据的存放位置（如把日志与数据分盘）与存储分配
	- 存取方法：索引（B+ 树索引适合范围查询与排序，哈希索引适合等值查询，位图索引适合低基数列）
	- 索引的选择原则：在 WHERE、JOIN、ORDER BY 中频繁出现的列上建索引；数据量小或更新极频繁的列不宜建索引
- 评价重点：查询响应时间、存储空间利用率、事务吞吐量；若达不到要求则返回逻辑设计阶段重新调整

	- C语言：EXEC SQL<SQL 语句>;
	- Java：#SQL {<SQL 语句>};
- 实例（例 8.1）：依次检查某个系的学生记录，交互式更新某些学生年龄
```c
EXEC SQL BEGIN DECLARE SECTION;          /* 主变量说明开始 */
    char deptname[20];
    char hsno[9];
    char hsname[20];
    char hssex[2];
    int  HSage;
    int  NEWAGE;
EXEC SQL END DECLARE SECTION;            /* 主变量说明结束 */
long SQLCODE;
EXEC SQL INCLUDE SQLCODE;                /* 定义 SQL 通信区 */

int main(void)                           /* C 语言主程序开始 */
{
    int  count = 0;
    char yn;                             /* 变量 yn 代表 yes 或 no */
    printf("Please choose the department name(CS/MA/IS): ");
    scanf("%20s", &deptname);            /* 为主变量 deptname 赋值 */
    EXEC SQL CONNECT TO TEST@localhost:54321 USER "SYSTEM"/"MANAGER";
                                         /* 连接数据库 TEST */
    EXEC SQL DECLARE SX CURSOR FOR       /* 定义游标 SX */
        SELECT Sno, Sname, Ssex, Sage    /* SX 对应的语句 */
        FROM Student
        WHERE SDept = :deptname;

    EXEC SQL OPEN SX;                    /* 打开游标 SX，指向查询结果的第一行 */
    for (;;)                             /* 用循环结构逐条处理结果集中的记录 */
    {
        EXEC SQL FETCH SX INTO :HSno, :HSname, :HSsex, :HSage;
        /* 推进游标，将当前数据放入主变量 */
        if (SQLCA.SQLCODE != 0)          /* SQLCODE != 0，表示操作不成功 */
            break;                       /* 利用 SQLCA 中的状态信息决定何时退出循环 */
        if (count++ == 0)                /* 如果是第一行的话，先打出行头 */
            printf("\n%-10s %-20s %-10s %-10s\n", "Sno", "Sname", "Ssex", "Sage");
        printf("%-10s %-20s %-10s %-10d\n", HSno, HSname, HSsex, HSage);
                                         /* 打印查询结果 */
        printf("UPDATE AGE(y/n)?");      /* 询问用户是否要更新该学生的年龄 */
        do { scanf("%c", &yn); }
        while (yn != 'N' && yn != 'n' && yn != 'Y' && yn != 'y');
        if (yn == 'y' || yn == 'Y')      /* 如果选择更新操作 */
        {
            printf("INPUT NEW AGE:");
            scanf("%d", &NEWAGE);        /* 用户输入新年龄到主变量中 */
            EXEC SQL UPDATE Student      /* 嵌入式 SQL 更新语句 */
                SET Sage = :NEWAGE
                WHERE CURRENT OF SX;     /* 对当前游标指向的学生年龄进行更新 */
        }
    }
    EXEC SQL CLOSE SX;                   /* 关闭游标 SX，不再和查询结果对应 */
    EXEC SQL COMMIT WORK;                /* 提交更新 */
    EXEC SQL DISCONNECT TEST;            /* 断开数据库连接 */
}
```

	- 找出公共子表达式
### 物理优化
- 物理优化：选择高效合理的操作算法或存取路径
- 基于启发式规则：
	- 选择操作
	- 连接操作
- 基于代价估算的优化
	- 计算过各种操作算法的执行代价，所需信息存在数据字典中
	- 代价模型：代价 = 磁盘 I/O 次数 + CPU 时间 + 内存开销，通常以页面读取次数为主
	- 选择操作的实现与代价：全表扫描（读全部页）、索引扫描（读索引页 + 数据页）
	- 连接操作的实现与代价：
		- 嵌套循环连接：外表每读一个元组就扫描一遍内表，代价与外表的元组数成正比
		- 排序-合并连接：先按连接属性排序再归并，适合已排序或有大索引的情况
		- 索引连接：内表连接属性上有索引时，用外表每个值去查索引，效率最高
		- 哈希连接：用连接属性做哈希，适合等值连接且内存足够时
	- 选择规则：优先选代价最小的方案；小关系做外表、大关系做内表时嵌套循环更省 I/O
# 数据库恢复技术
## 事务的基本概念
- 事务：是用户定义的一个数据库操作序列
- 定义事务：`BEGIN TRANSACTION;`
- 提交事务：`COMMIT;`
- 回滚事务：`ROLLBACK;`
- ACID特性：原子性、一致性、隔离性和持续性
### 事务的状态
![[事务状态转换.svg]]
- 活动状态：事务正在执行
- 部分提交状态：最后一条语句已执行，但修改可能还在内存缓冲区，尚未真正写回磁盘
- 提交状态：修改已全部写入磁盘，事务成功结束
- 失败状态：事务因错误或系统故障无法继续
- 中止状态：事务已回滚，数据库恢复到事务开始前的状态；被中止的事务可以重新执行
- 状态迁移：活动 → 部分提交 →（提交）提交；活动/部分提交 →（出错）失败 →（撤销）中止
## 故障的种类
- 事物内部的故障
	- 非预期的、不能由应用程序处理的
	- 事务撤销（UNDO），强行回滚
- 系统故障（软故障）
	- 造成系统停止的事件，要重启系统
	- 重做（REDO）所有已提交事务
- 介质故障（硬故障）
	- 外存故障
- 计算机病毒
## 恢复的实现技术
### 数据转储
- 其实就是备份，十分耗费时间资源
- 静态转储：在一致性状态中转储，转储期间不能存取修改
- 动态转储：转储期间可以存取修改
- 海量转储、增量转储
### 登记日志文件
- 日志文件是用来记录事务对数据库的更新操作的文件
- 日志文件中登记的内容是：各个事务开始、结束标记和更新操作，也称为日志记录
- 日志记录的内容包括：事务标识、操作类型、操作对象、旧数据、新数据
- 日志的作用：进行书屋故障恢复和系统故障恢复，并协助后备副本将进行介质故障回复
- 登记日志文件的原则
	- 登记的次序严格按并发事务执行的时间次序
	- 必须先写日志文件，后写数据库
## 恢复策略
### 事务故障的恢复
1. 反向扫描日志文件，查找该事务的更新操作
2. 对该事务的更新操作执行逆操作
3. 重复1、2
4. 读到该事务的开始标记，停止扫描
### 系统故障的恢复
1. 正向扫描日志文件，查找故障发生前提交的事务，记入重做队列；故障发生时未完成的事务，计入撤销队列
2. 对撤销队列的事务进行撤销处理
3. 对重做队列的事务进行重做处理
### 介质故障的恢复
1. 重装数据库，装入最新的后备副本
2. 装入相应的日志文件副本，重做已完成的事务
## 具有检查点的恢复技术
- 在日志文件中增加检查点记录和重新开始文件
- 检查点记录的内容包括：建立检查点时刻所有正在执行的事务清单、这些事务最近的一个日志记录地址
- 重新开始文件用来记录各检查点记录在日志文件中的地址
### 检查点恢复的判断规则
- 从重新开始文件中找到最后一个检查点记录，得到检查点时刻正在执行的事务清单 ACTIVE
- 从检查点开始正向扫描日志：
	- 在检查点前已提交的事务 → 放入重做（REDO）队列
	- 在检查点后提交的事务 → 放入重做（REDO）队列
	- 在故障发生时尚未完成的事务 → 放入撤销（UNDO）队列
- 对 UNDO 队列事务反向执行逆操作，对 REDO 队列事务正向重做
- 好处：不需要扫描整个日志，只需从最近检查点开始，缩短了恢复时间
### 恢复策略小结
- 事务故障：反向扫描日志，UNDO 该事务，不需要重做
- 系统故障：UNDO 未提交事务，REDO 已提交但未写回磁盘的事务
- 介质故障：装入后备副本 + 装入日志副本做 REDO
- 恢复的基本原则：先写日志后写数据库（Write-Ahead Logging），保证日志中的记录一定比数据库中的修改更新
# 并发控制
## 并发控制概述
- 事务是并发控制的基本单位
- 数据不一致问题：
	- 丢失修改：两个事务同时读入并修改，其中一个事务的修改丢失
	- 不可重复读：T1读取后T2修改数据，导致T1不可再读（读到不同数据或读到不存在数据）
	- 读脏数据：T1修改数据后T2读取，T1撤销修改，T2读到的就是脏数据（与数据库不符合）
- 并发控制方法：封锁、时间戳、乐观控制法、多版本并发控制MVCC
## 封锁
- 排他锁（X锁）：只有T可读取修改A，且不能再加锁
- 共享锁（S锁）：都可读不可改，但其他T也只能加S锁
## 封锁协议
- 封锁协议：封锁需要约定的规则
- 一级封锁协议：T在修改R前必须加X锁，结束后释放
- 二级封锁协议：一级基础上，在读取R之前必须加S锁，读完后释放
- 三级封锁协议：一级基础上，在读取R之前必须加S锁，事务后释放
### 封锁协议与一致性级别的对应
| 协议 | 加锁规则 | 能保证的一致性 | 不能避免的问题 |
| --- | --- | --- | --- |
| 一级封锁协议 | 修改前加 X 锁，事务结束才释放 | 不丢失修改 | 脏读、不可重复读 |
| 二级封锁协议 | 一级 + 读前加 S 锁，读完立即释放 S 锁 | 不丢失修改、不读脏数据 | 不可重复读 |
| 三级封锁协议 | 一级 + 读前加 S 锁，事务结束才释放 | 不丢失修改、不读脏数据、可重复读 | 幻读（需配合谓词锁或间隙锁） |
- 记忆要点：X 锁“写锁到期才放”，S 锁“一级不放、二级读完就放、三级到期才放”
- 封锁协议与隔离级别的关系：一级≈READ UNCOMMITTED 的加强、二级≈READ COMMITTED、三级≈REPEATABLE READ
## 活锁和死锁
（a）活锁——T2 一直等待，T3、T4 不断插队，事务 T2 被“饿死”：

| T1 | T2 | T3 | T4 |
| --- | --- | --- | --- |
| lock R | | | |
| ⋮ | Lock R | | |
| | 等待 | Lock R | |
| | 等待 | ⋮ | Lock R |
| Unlock R | 等待 | | 等待 |
| | 等待 | Lock R | 等待 |
| | 等待 | ⋮ | 等待 |
| | 等待 | Unlock R | |
| | 等待 | | Lock R |

（b）死锁——T1、T2 互相等待对方持有的锁：

| T1 | T2 |
| --- | --- |
| Lock R1 | |
| ⋮ | Lock R2 |
| Lock R2 | ⋮ |
| 等待 | Lock R1 |
| 等待 | 等待 |
| 等待 | 等待 |
### 活锁
- 解决办法：先来先服务
### 死锁
- 预防：
	- 一次封锁法：
		- 一次将所有要使用的数据加锁，否则不执行
		- 缺点：降低并发度
	- 顺序封锁法：
		- 规定封锁顺序，所有事务按顺序封锁
		- 维护顺序的成本高、封锁困难
- 诊断与解除：
	- 诊断：
		- 超时法：一个事务等待时间超过阈值就认为死锁，实现简单但可能误判（长事务）
		- 事务等待图法：节点是事务，若 T1 等待 T2 释放锁则画有向边 T1→T2；图中**出现回路即死锁**
			- 周期性生成等待图并检测回路，发现回路则选择一个牺牲事务回滚
	- 解除：选择代价最小的事务（已执行时间最短、持锁最少、回滚代价最小），撤销再修复
## 并发调度的可串行性
- 可串行化调度：多个事务的并发执行与串行执行结果相同
- 可串行性是并发事务正确调度的准则
- 冲突可串行化调度：
	- 冲突操作：不同事物对同一个数据的读写操作和写写操作都是冲突操作
	- 冲突可串行化调度是可串行化调度的充分条件
## 两段锁协议（2PL）
- 2PL实现并发调度的可串行性
- 第一阶段：获得封锁（扩展阶段）
	- 事务可以申请获得任何数据项上的任何锁，但是不能释放任何锁
- 第二阶段：释放封锁（收缩阶段）
	- 事务可以释放任何数据项上的任何锁，但是不能再申请任何锁
- 2PL是实现可串行化调度的充分条件（但可串行化的调度不一定是 2PL 调度）
- 2PL 只保证可串行化，仍可能发生死锁；严格 2PL 要求所有锁在事务结束才释放，可避免级联回滚
- 遵守 2PL 的事务其冲突操作次序与某个串行执行相同，这就是“冲突可串行化”的判定依据
## 封锁的粒度
- 封锁粒度：封锁对象的大小（逻辑单元、物理单元）
- 封锁粒度越大，系统的并发度越小，并发控制的开销越小
### 多粒度封锁
- 按粒度等级划分多粒度树
- 多粒度树的每个节点能独立地加锁（所有子节点也被加同样的锁）
- 显式封锁：直接被加锁
- 隐式封锁：作为子节点，由于父节点加锁而被加锁
- 检查加锁冲突需要遍历，麻烦
### 意向锁
- 标记其子节点正在被加锁
- 意向共享锁（IS锁）：子节点意向加S锁
- 意向排他锁（IX锁）：子节点意向加X锁
- 共享意向排他锁（SIX锁）：对此节点加S锁，子节点意向加X锁

| DATE / TIME / DATETIME / TIMESTAMP / YEAR | 3/3/8/4/1 | 日期时间；TIMESTAMP 受时区影响，范围只到 2038 年 |
### 索引
- 作用：加快查询（本质是把无序数据变成有序结构以减少磁盘 I/O），代价是降低写入速度、占用空间
- 分类：主键索引、唯一索引、普通索引、全文索引、联合索引
- 创建：`CREATE [UNIQUE|FULLTEXT] INDEX 索引名 ON 表名(字段名[, 字段名...]);`
- 删除：`DROP INDEX 索引名 ON 表名;`
- 最左前缀原则：联合索引 `(a, b, c)` 只能被 `a`、`a,b`、`a,b,c` 这样的条件命中，跳过最左列会失效
- 索引失效的常见情况：对索引列做函数运算或表达式计算、`LIKE '%x'` 前置通配、隐式类型转换、`OR` 连接的条件中有列无索引、使用 `!=` 或 `IS NOT NULL` 导致全表扫描
## DML 数据操纵
### 添加数据
- 指定字段插入：`INSERT INTO 表名(字段1, 字段2, ...) VALUES (值1, 值2, ...);`
- 全字段插入：`INSERT INTO 表名 VALUES (值1, 值2, ...);`
- 批量插入：`INSERT INTO 表名 VALUES (...), (...), (...);`（比多条单行插入快得多）
- 插入查询结果：`INSERT INTO 表名 SELECT ... FROM 另一张表;`
### 修改数据
- `UPDATE 表名 SET 字段1 = 值1, 字段2 = 值2 [WHERE 条件];`
- 不加 WHERE 会修改全表，务必先 `SELECT` 验证条件
- 把字段置空：`SET 字段 = NULL`（注意该字段不能有 NOT NULL 约束）
### 删除数据
- `DELETE FROM 表名 [WHERE 条件];`（不加 WHERE 删全表，可回滚）
- 无法用 DELETE 删除字段本身（删字段用 `ALTER TABLE ... DROP`）
- 外键有级联删除时，删除主表记录会连带删除子表记录
## DQL 数据查询
- 编写顺序：`SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT`
- 执行顺序：`FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT`（所以 WHERE 中不能用 SELECT 里定义的别名，ORDER BY 中可以用）
### 基础查询
- 查询多个字段：`SELECT 字段1, 字段2 FROM 表名;`；查询全部：`SELECT * FROM 表名;`（生产环境不推荐 `*`）
- 设置别名：`SELECT 字段1 AS 别名1 FROM 表名 AS 别名;`（AS 可省略）
- 去除重复行：`SELECT DISTINCT 字段列表 FROM 表名;`（作用于整行组合）
### 条件查询
- `SELECT 字段列表 FROM 表名 WHERE 条件列表;`

| 比较运算符 | 含义 | 逻辑运算符 | 含义 |
| --- | --- | --- | --- |
| `>` `>=` `<` `<=` `=` | 大小比较 | `AND` / `&&` | 并且 |
| `!=` 或 `<>` | 不等于 | `OR` / `\|\|` | 或者 |
| `BETWEEN ... AND ...` | 区间，包含两端 | `NOT` / `!` | 取反 |
| `IN (...)` | 等于列表中的任意一个 | | |
| `LIKE 占位符` | 模糊匹配：`_` 匹配一个字符，`%` 匹配任意个字符 | | |
| `IS NULL` / `IS NOT NULL` | 判断空值 | | |
### 聚合函数
- `SELECT 聚合函数(字段列表) FROM 表名;`（聚合函数对 NULL 值不计数）

| 聚合函数 | 作用 |
| --- | --- |
| `COUNT(字段或*)` | 统计行数，`COUNT(*)` 统计所有行，`COUNT(字段)` 跳过 NULL |
| `MAX(字段)` / `MIN(字段)` | 最大值 / 最小值 |
| `AVG(字段)` | 平均值 |
| `SUM(字段)` | 求和 |
### 分组查询
- `SELECT 分组字段, 聚合函数(字段) FROM 表名 [WHERE 分组前条件] GROUP BY 分组字段 [HAVING 分组后条件];`
- 执行顺序：`WHERE > 聚合函数 > HAVING`；`WHERE` 不能跟聚合函数，`HAVING` 可以
- 只出现在 `SELECT` 中而不在聚合函数里的列，必须出现在 `GROUP BY` 中（`ONLY_FULL_GROUP_BY` 模式下强制）
### 排序与分页
- 排序：`SELECT 字段列表 FROM 表名 ORDER BY 字段1 ASC|DESC, 字段2 ASC|DESC;`（升序 ASC 为默认）
- 分页：`SELECT 字段列表 FROM 表名 LIMIT 起始索引, 查询记录数;`
	- 起始索引从 0 开始，公式：`起始索引 = (页码 - 1) × 每页记录数`
	- `LIMIT n` 等价于 `LIMIT 0, n`

## 约束
- 约束作用于表中字段，可在建表时定义，也可用 `ALTER TABLE` 追加或删除

| 约束 | 关键字 | 说明 |
| --- | --- | --- |
| 非空约束 | `NOT NULL` | 该列不允许为 NULL |
| 唯一约束 | `UNIQUE` | 该列值不能重复，但可为 NULL |
| 主键约束 | `PRIMARY KEY` | 唯一且非空，一张表只能有一个 |
| 默认约束 | `DEFAULT` | 未给值时使用默认值 |
| 检查约束 | `CHECK` | 满足条件才允许写入（MySQL 8.0.16 起真正生效） |
| 外键约束 | `FOREIGN KEY` | 关联另一张表的主键，保证参照完整性 |
| 自动增长 | `AUTO_INCREMENT` | 整数主键自动递增 |

### 外键
- 建表时添加：
```sql
CREATE TABLE 表名(
    字段名 类型,
    [CONSTRAINT 外键名称] FOREIGN KEY (外键字段名) REFERENCES 主表(主表列名)
);
```
- 建表后添加：`ALTER TABLE 表名 ADD CONSTRAINT 外键名称 FOREIGN KEY (外键字段名) REFERENCES 主表(主表列名);`
- 删除外键：`ALTER TABLE 表名 DROP FOREIGN KEY 外键名称;`
- 删除/更新行为：

| 行为 | 说明 |
| --- | --- |
| `NO ACTION` | 父表记录被子表引用时，不允许删除/修改 |
| `RESTRICT` | 与 NO ACTION 相同，立即检查 |
| `CASCADE` | 父表删除/修改时，子表对应记录连带删除/修改 |
| `SET NULL` | 父表删除/修改时，子表外键置为 NULL（该列必须允许 NULL） |
| `SET DEFAULT` | 父表删除/修改时，子表外键置为默认值（InnoDB 不支持） |

- 指定行为：`ALTER TABLE 表名 ADD CONSTRAINT 外键名称 FOREIGN KEY (外键字段) REFERENCES 主表(字段) ON UPDATE 行为 ON DELETE 行为;`
## 多表查询
### 多表关系
- 一对多（多对一）：如部门与员工，在“多”的一方建外键指向“一”的一方的主键
- 多对多：如学生与课程，需要第三张中间表，中间表至少包含两个外键分别关联两张表的主键
- 一对一：任意一方加入外键关联另一方主键，并给外键加 `UNIQUE` 约束
### 连接查询
- 内连接（只保留两表匹配的行，条件一般是主键 = 外键）
	- 隐式：`SELECT 字段列表 FROM 表1, 表2 WHERE 条件;`
	- 显式：`SELECT 字段列表 FROM 表1 [INNER] JOIN 表2 ON 条件;`
- 外连接（保留一侧不匹配的行，另一侧补 NULL）
	- 左外：`SELECT 字段列表 FROM 表1 LEFT [OUTER] JOIN 表2 ON 条件;`
	- 右外：`SELECT 字段列表 FROM 表1 RIGHT [OUTER] JOIN 表2 ON 条件;`
- 自连接：`SELECT 字段列表 FROM 表1 别名1 JOIN 表1 别名2 ON 条件;`（同一张表当两张表用，必须起别名）
### 联合查询
- 把多次查询的结果纵向合并，要求列数与数据类型一致
- `SELECT ... FROM 表1 UNION [ALL] SELECT ... FROM 表2;`
- `UNION ALL` 不去重（快），`UNION` 去重并排序（慢）
### 子查询
- 一条 SQL 中嵌套 SELECT 语句，按结果分为标量子查询、列子查询、行子查询、表子查询
- 常用位置：`WHERE 字段 = (SELECT ...)`、`WHERE 字段 IN (SELECT ...)`、`FROM (SELECT ...) 别名`、`EXISTS (SELECT ...)`
- `EXISTS` 只判断子查询是否返回行，通常比 `IN` 快；`NOT IN` 遇到 NULL 会返回空结果，应改用 `NOT EXISTS`
## 事务
- 事务把一组操作看作一个整体，要么全部成功，要么全部失败
### 操作
- 开启事务：`START TRANSACTION;`（或 `BEGIN;`）
- 提交事务：`COMMIT;`
- 回滚事务：`ROLLBACK;`
- 保存点：`SAVEPOINT 点名;` 与 `ROLLBACK TO 点名;`（可回滚到中间状态）
### 四大特性（ACID）
- 原子性（Atomicity）：事务是最小操作单位，要么全做要么全不做，靠 undo log 实现
- 一致性（Consistency）：事务前后数据满足完整性约束，是事务的目的
- 隔离性（Isolation）：并发事务之间互不干扰，靠锁与 MVCC 实现
- 持久性（Durability）：提交后修改永久保存，靠 redo log 实现
### 并发事务问题

| 问题 | 描述 |
| --- | --- |
| 脏读 | 一个事务读到了另一个事务尚未提交的数据 |
| 不可重复读 | 同一事务内两次读到同一行的值不同（别人 UPDATE 并提交了） |
| 幻读 | 同一事务内两次按相同条件查询，第二次多出了别人新插入的行 |
### 隔离级别

| 隔离级别（从松到严） | 脏读 | 不可重复读 | 幻读 |
| --- | --- | --- | --- |
| READ UNCOMMITTED | 可能出现 | 可能出现 | 可能出现 |
| READ COMMITTED | 不会 | 可能出现 | 可能出现 |
| REPEATABLE READ（MySQL 默认） | 不会 | 不会 | 可能出现（InnoDB 用间隙锁基本解决） |
| SERIALIZABLE | 不会 | 不会 | 不会 |

- 查看与设置：`SELECT @@TRANSACTION_ISOLATION;`、`SET [SESSION|GLOBAL] TRANSACTION ISOLATION LEVEL 级别;`
- 级别越高一致性越好、并发度越低；MySQL 的 InnoDB 在 REPEATABLE READ 下用 MVCC 实现快照读，用间隙锁（Next-Key Lock）防止幻读
## MySQL 与标准 SQL 的差异小结
- 分页：标准 SQL 用 `OFFSET/FETCH`，MySQL 用 `LIMIT`
- 自增列：MySQL 用 `AUTO_INCREMENT`，SQL 标准用 `IDENTITY` 或序列
- 字符串拼接：MySQL 用 `CONCAT()`，标准 SQL 用 `||`
- 日期函数、类型名称与长度语义（`VARCHAR` 是否按字节/字符）各家不同
- 大小写：MySQL 关键字不敏感，库名/表名在 Linux 上敏感
- 视图更新：MySQL 只允许对“一对一映射基本表”的简单视图做更新
